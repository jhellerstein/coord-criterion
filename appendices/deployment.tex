\section{Availability and Confluence under a Deployment}
\label{app:deployment}

Complete CAP (Theorem~\ref{thm:complete-cap}) requires every participant to be
able to emit every output in its fiber.  A deployment restricts which rows each
participant may emit.  This appendix restricts Availability accordingly and
characterizes the resulting compatibility condition.

\begin{definition}[Deployment, separable run family]
\label{def:deployment}
A \emph{deployment} over a finite participant set $P$ assigns to each $p\in P$
a set $A_p\subseteq S$, the rows $p$ may emit: $p$ performs an output event
$\Out{\gamma}{o}$ (Definition~\ref{def:system-output-event}) at current input
$i$ only if $(i,o)\in A_p$.  A \emph{partition} $\Pi$ of $P$ divides $P$ into
two or more nonempty components, as in a partitioned history
(Definition~\ref{def:partition-notions}).

A \emph{participant run family} assigns to each of finitely many participants
$p\in P$ an initial input and a canonical run whose emitted rows lie in $A_p$.
A participant whose run emits no output is \emph{silent}.  The family is
\emph{separable under $\Pi$} when either participants in at least two
components emit, or exactly one distinct row is emitted and some silent
participant lies in another component.
\end{definition}

\begin{definition}[Monotone across partitions]
\label{def:monotone-across-partitions}
Relative to a deployment, $\Spec$ is \emph{monotone across $\Pi$} when, for
every participant run family separable under $\Pi$ and every common \indesc $j$
of its participants' current inputs, some $u\in\fiber{j}$ \outrel every
emitted output.  It is \emph{monotone across partitions} when it is monotone
across every partition of $P$.
\end{definition}

This is the common-\indesc condition
(Definition~\ref{def:common-expansion-condition}) restricted to the families a
partition can separate, so Lifted Monotonicity implies monotonicity across
partitions.  Two choices available to one participant never form a separable
family: one run never emits incompatible outputs, and the silent-participant
case requires a single distinct row.  The converse can therefore fail: for
example, when every incompatible family of two or more authorized rows is
confined to one participant's authority (and single authorized rows lift), as
in leader election where one participant names the leader.  If $|P|\ge2$ and
$A_p=S$ for every $p$, every pair of rows can be split across a partition and
every single row paired with a silent participant at the common \indesc; since
pairs of rows suffice for the common-\indesc condition
(Section~\ref{sec:lifted-monotonicity}), monotonicity across partitions is then
Lifted Monotonicity.

\begin{definition}[Deployment Availability]
\label{def:deployment-availability}
Relative to a deployment, a system has \emph{Deployment Availability} when, at
every consistent cut of every partitioned history over $P$ it produces, each
participant $p$ in state $(i,R)$ can emit every $o\in R(i)$ with
$(i,o)\in A_p$ in some continuation, produced by the system and partitioned by
the same components, that adds only history events of $p$'s component and no
input event.
\end{definition}

As in Availability (Definition~\ref{def:partition-notions}), the output event
may apply commitments within the participant's component.  If $A_p=S$ for
every $p$, Deployment Availability is Availability for histories over $P$.  We
call a deployment \emph{single-authority} when one participant holds all
relevant input and output choices and every other participant is silent; the
formalism permits it, as do placement-sensitive models such as
relational-transducer CALM~\cite{ameloot2013relational,ameloot2015weaker}, but
it is degenerate and we set it aside.

\begin{proposition}[Partition compatibility under a deployment]
\label{thm:complete-cap-deployment}
Fix a deployment.  The following are equivalent.
\begin{enumerate}
  \item For every partition $\Pi$, every participant run family separable
        under $\Pi$ is confluent at every common \indesc $j$ of its
        participants' current inputs.
  \item $\Spec$ is monotone across partitions.
\end{enumerate}
\end{proposition}

\begin{proof}
Fix $\Pi$, a separable family, and $j$, and let $E$ be the set of emitted
outputs.  By Lemma~\ref{lem:reconciliation}, the family is confluent at $j$ if
and only if some $u\in\fiber{j}$ \outrel every output in $E$.  The two
conditions thus agree family by family.
\end{proof}

The proposition does not use Deployment Availability.  Combined with it, the
outputs that components emit independently under authorized placement have a
common \outnoun $u$ in the specification.  It does not follow that the
deployment authorizes any participant to emit $u$; confluence through legal
output events of the deployment would additionally require that authority, a
condition we do not impose.  With $|P|\ge2$ and $A_p=S$ for every $p$, the
proposition is the common-survivor step (Proposition~\ref{prop:confluence})
behind Theorem~\ref{thm:complete-cap}.

\subsection{Registers}
\label{app:registers}

The Gilbert--Lynch witness, a replica cut off from a completed write that must
still answer a read, is recovered by Corollary~\ref{cor:gilbert-lynch}
(Appendix~\ref{app:cap-response}).  Here both writes are visible to both
replicas.

An input is a finite causally closed operation history, with $h\InputOrd h'$
when restricting $h'$ to the operations of $h$ gives $h$.  An output is an
explanation $(L,\rho)$: $L$ is an operation order allowed by the consistency
model and $\rho$ maps each completed read to the write supplying its response.
One explanation \outrel another when it extends $L$ without reversing an
existing order and extends $\rho$ without changing an answered read.  This is
the register of Appendices~\ref{app:cap-response} and~\ref{sec:frontiers} with
a different output record.

Two replicas start empty.  Participant $p$ completes $w_p(x,\dog)$ while $q$
concurrently completes $w_q(x,\catv)$; the replicas exchange both writes, a
partition separates them, and each serves a local read.

Under linearizability $L$ is a total order extending real
time~\cite{herlihy1990linearizability}.  If $p$ reads \catv, its explanation
requires $w_p(x,\dog)<_L w_q(x,\catv)$; if $q$ reads \dog, it requires the
opposite.  No explanation \outrel both, so the register is not monotone across
the partition $\{\{p\},\{q\}\}$ under any deployment authorizing these two
reads.

Under causal consistency~\cite{lamport1978time,ahamad1995causal} the writes
stay concurrent, and one explanation assigns $p$'s read to \catv{} and $q$'s
to \dog{}.  Two answers to the same read remain incompatible, but under a
deployment in which each participant answers only its own reads, such a pair
is confined to one participant and is never separable.  The causal register is
then monotone across partitions, and a commitment selecting a participant's
response is local to its component.
