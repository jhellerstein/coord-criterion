\section{Ambiguous Specifications and Lifted Monotonicity}
\label{sec:ambiguous-specifications}

A functional specification fixes one output at each input, so its commitments
do one job: they seal inputs that could still arrive.  We now allow a fiber to
contain several outputs and ask when one output can \outrelbase them all as
input \ingrows.  Several outputs per input bring a second job, \emph{choosing} among
permitted outputs, and this section shows that sealing and choosing are the
only two.  Section~\ref{sec:ambiguity-story} introduces the issue by
example.  Section~\ref{sec:relational-specifications} defines relational
specifications and Lifted Monotonicity.  Section~\ref{sec:safe-exposure} lifts
output events and classifies commitments, and
Section~\ref{sec:relational-executions} shows that the run-level results of
Section~\ref{sec:determination} carry over and characterizes Consistency by a
condition on the table.

\label{sec:ambiguity-story}

several outputs at the same input.  Transaction ordering requires a choice
between incompatible serialization orders.  Traceroute observations, by
contrast, can all be \outrelpast by a larger route set.

\paragraph{Output choice and directedness.} The examples differ in what happens
to alternative outputs when one is emitted.  In panel~(f), neither
serialization order \outrel the other, so emitting one requires a
\emph{choice commitment} that removes the other while the input stays legal:
the system chooses.  In panel~(g), larger route sets \outrelbase both the
emitted observation and the outputs of the rows it removes.  We call such
removal an \emph{output retirement}
(Definition~\ref{def:output-retirement}); because every removed output is
\outrelpast by a remaining one, emitting the route observation needs no
commitment: it is \emph{exposable}.  The atomic event
$\Out{\gamma}{o}$ applies a sequence $\gamma$ of commitments, performs any
retirements, then emits $o$.

In Figure~\ref{fig:ambiguity-frames}, serialization requires commitment; traceroute avoids it.
The difference is the order-theoretic concept of a \emph{directed} fiber:
every finite set of outputs in the fiber has a common \outnoun there.
Directedness at a single input is not sufficient, however;
we must also \outrelbase prior outputs as input \ingrows. \emph{Lifted Monotonicity}
combines the requirements: every finite set of outputs possible at an input
must have a common \outnoun in the fiber of every \indesc.  Equivalently,
outputs emitted at inputs with a common \indesc $j$ must have a common
\outnoun permitted at $j$: the same test as in Section~\ref{sec:election-story}, read
with many outputs per input.  Two runs that emit $[A,B]$ and $[B,A]$ fail it;
two traceroute runs that emit different route sets pass it, since their union
survives in both.

\paragraph{Different commitment bases.}
The specification says which serialization orders are permitted; the
\emph{commitment basis} (Appendix~\ref{app:bases}) says which binding choices a system can make.
Figure~\ref{fig:cc-commitments} applies two different bases to the same three-transaction
fiber---one captures two-phase locking (2PL), the other multi-version timestamp ordering (MVTO).
In 2PL, racing for a lock commits orderings among a subset of transactions:
in this case it commits only to $A$ before $B$, leaving $C$'s position
open.  By contrast, timestamp assignment in MVTO orders a transaction with respect to all others:
in this case, $B$ is assigned first place.  Both are choices: they remove
serialization orders while the input stays legal, but leave different
alternatives open.
Each is one of the commitments an output event applies in emitting a full
serial order.  Whatever the protocol, its runs are equivalent to
canonical runs (Lemma~\ref{lem:canonical-equivalent}), and Consistency is
judged on those.  Appendix~\ref{app:cc-bases} gives the full bases, including
abort commitments, which fix a transaction as aborted.

\subsection{Relational specifications and Lifted Monotonicity}
\label{sec:relational-specifications}

The examples pose the specification-level question: when can every finite set
of possible outputs survive together as input \ingrows?  Lifted Monotonicity
answers it by requiring monotonicity of fibers.  We first define the two ways
it can fail, then combine them.

\begin{definition}[Ordered relational specification]
\label{def:relational-specification}
An \emph{ordered relational specification} is
        \begin{equation}
  \Spec=(I,\InputOrd,O,\OutputOrd,S),
  \qquad S\subseteq I\times O,
  \label{eq:relational-specification}
        \end{equation}
where $(I,\InputOrd)$ and $(O,\OutputOrd)$ are partially ordered sets and $S$
is total on $I$: every input appears in at least one row.  The specification
is \emph{ambiguous} when some fiber contains more than one output.  A row $(i,o)\in S$
says that output $o$ is permitted at input $i$.  The fiber
        \begin{equation}
  \fiber{i}=\{o\in O:(i,o)\in S\}
  \label{eq:fiber}
        \end{equation}
of Section~\ref{sec:functional-specifications} may now contain several
outputs.  A functional specification is the special case
$\fiber{i}=\{f(i)\}$.
\end{definition}

Specification states, commitment bases, and input events
(Sections~\ref{sec:functional-specifications} and~\ref{sec:functional-events})
apply unchanged to relational tables; Section~\ref{sec:safe-exposure} lifts
output events.

\begin{definition}[Relational Monotonicity]
\label{def:relational-monotonicity}
An ordered relational specification satisfies \emph{Relational Monotonicity}
when every output keeps some \outnoun as input \ingrows:
        \begin{equation}
  i\InputOrd j,\ o\in\fiber{i}
  \quad\Longrightarrow\quad
  \exists u\in\fiber{j}.\ o\OutputOrd u.
  \label{eq:relational-monotonicity}
        \end{equation}
\end{definition}

For singleton fibers this is functional monotonicity,
Equation~\ref{eq:functional-monotonicity}.  It treats each output separately
and does not say whether several outputs permitted at one input have a
common \outnoun; Directed Outputs (Definition~\ref{def:fiber-directedness})
addresses that question.

\begin{definition}[Compatibility]
\label{def:compatibility}
Let $F\subseteq O$ be a set of outputs.  Outputs $o_1,\ldots,o_k$ are
\emph{compatible in $F$} if some $u\in F$ \outrel all of them,
$o_r\OutputOrd u$ for every $r$, and \emph{incompatible in $F$} otherwise.
They are \emph{compatible at input $i$} when they are compatible in the fiber
$\fiber{i}$.
\end{definition}

\begin{definition}[Directed fiber, Directed Outputs]
\label{def:fiber-directedness}
A fiber $F\subseteq O$ is \emph{directed} when every nonempty finite
$X\subseteq F$ is compatible in $F$.  An ordered relational specification has
\emph{Directed Outputs} when every fiber $\fiber{i}$ is directed.
\end{definition}

A singleton fiber is directed, and closure under a join is sufficient but not
necessary.  Directedness requires some upper bound within the fiber for each finite
set, not a least one or a fixed merge operator, so it is weaker than a
join-semilattice.  Compatibility likewise does not require comparability: two
incomparable outputs may have a third output in the fiber that \outrel both.  Thus the
traceroute fiber is directed by union, whereas the two transaction orders in
Figure~\ref{fig:ambiguity-frames}(f) are incompatible.

\paragraph{Lifted Monotonicity.}

Relational Monotonicity gives each output a \outnoun at every \indesc of its
input; Directed Outputs gives each finite set within a fiber a common \outnoun.  The joint lift
expresses both.  For nonempty $A,B\subseteq O$, define
        \begin{equation}
  A\LiftedOrd B
  \;\Longleftrightarrow\;
  \text{every nonempty finite }X\subseteq A\text{ is compatible in }B,
  \label{eq:joint-output-order}
        \end{equation}
the \emph{joint lift} of $\OutputOrd$.  Unlike Relational Monotonicity, it
treats finite sets of outputs together rather than each output separately,
and $A\LiftedOrd A$ holds exactly when $A$ is directed.

\begin{definition}[Lifted Monotonicity, monotone specification]
\label{def:lifted-monotonicity}
An ordered relational specification satisfies \emph{Lifted Monotonicity}, and
is called \emph{monotone}, when the mapping $i\mapsto\fiber{i}$ is monotone
under the joint lift:
        \begin{equation}
  i\InputOrd j
  \quad\Longrightarrow\quad
  \fiber{i}\LiftedOrd\fiber{j}.
  \label{eq:lifted-monotonicity}
        \end{equation}
\end{definition}

With singleton fibers it is functional monotonicity
(Definition~\ref{def:functional-monotonicity}).  Its third form below is a
condition on finite sets of rows, which Section~\ref{sec:relational-executions}
identifies with Consistency.

\begin{definition}[Common-\indesc condition]
\label{def:common-refinement-condition}
An ordered specification satisfies the \emph{common-\indesc condition} when,
for every finite set of rows $(i_1,o_1),\ldots,(i_k,o_k)$ of $S$ and every
common \indesc $j$ of $i_1,\ldots,i_k$, some $u\in S(j)$ \outrel every
$o_r$.
\end{definition}

The inputs $i_r$ need not be comparable, because different runs meet only at a
common \indesc.  For the empty set of rows the condition asks only that
$S(j)$ be nonempty, which totality guarantees.

The next proposition supplies
two forms used later: form~(2) separates the
across-input and within-fiber requirements, and form~(3) matches confluence by
allowing outputs from several inputs.

\begin{proposition}[Equivalent forms of Lifted Monotonicity]
\label{prop:lifted-monotonicity-decomposition}
For an ordered relational specification, the following are equivalent:
\begin{enumerate}
  \item Lifted Monotonicity: $i\InputOrd j$ implies
        $\fiber{i}\LiftedOrd\fiber{j}$;
  \item Relational Monotonicity and Directed Outputs;
  \item the common-\indesc condition
        (Definition~\ref{def:common-refinement-condition}): for every finite
        set of rows $(i_1,o_1),\ldots,(i_k,o_k)$ of $S$, the outputs
        $o_1,\ldots,o_k$ are compatible at every common \indesc of
          $i_1,\ldots,i_k$.
\end{enumerate}
\end{proposition}

\begin{proof}
(1) implies (2).  Taking $j=i$, $\fiber{i}\LiftedOrd\fiber{i}$ says that
$\fiber{i}$ is directed.  Taking $X=\{o\}$ for $o\in\fiber{i}$ and
$i\InputOrd j$ gives $u\in\fiber{j}$ with $o\OutputOrd u$, which is Relational
Monotonicity.

(2) implies (3).  Let rows $(i_r,o_r)$ have common \indesc $j$.  For the
empty family, totality gives $\fiber{j}\neq\varnothing$.  Otherwise, since
$i_r\InputOrd j$, Relational Monotonicity gives, for each $r$, a
$u_r\in\fiber{j}$ with $o_r\OutputOrd u_r$.  The $u_r$ now all lie in the one
fiber $\fiber{j}$, which is directed, so some $u\in\fiber{j}$ \outrel every
$u_r$, hence every $o_r$.

(3) implies (1).  Let $i\InputOrd j$ and $X\subseteq\fiber{i}$ be nonempty and
finite.  The rows $\{(i,x):x\in X\}$ have common \indesc $j$, so some
$u\in\fiber{j}$ \outrel all of $X$; that is $\fiber{i}\LiftedOrd\fiber{j}$.
\end{proof}

Checking pairs of rows suffices for form~(3), provided the pairs range over
all rows of $S$, including those at the common \indesc: combine two rows
into one row at $j$, then pair it with the next.  Pairs drawn only from
participants' initial decisions do not suffice; in the $k$-set agreement
example (participants must decide at most $k$ distinct values) of Appendix~\ref{app:additional-applications}, every $k$ of $k+1$
initial decisions are compatible, but not all of them.

\subsection{Lifted output events}
\label{sec:safe-exposure}

The functional case has one row per input, so an output event either removes
nothing or seals a legal input.  With several rows at one input, it can also
retire a \outrelpast row while retaining the row that \outrel it.  We now lift output events to this case and check that they satisfy the
facts about output events in Proposition~\ref{prop:canonical-output-preservation}.

\begin{definition}[Lifted output event]
\label{def:lifted-output-event}
Let $(i,R)$ be a state and $o\in R(i)$.  An output event $\Out{\gamma}{o}$
under a basis $\mathcal B$ (Appendix~\ref{app:bases}) applies a finite, possibly empty sequence
$\gamma=c_1\cdots c_n$ of commitments from $\mathcal B$, each $c_m$ defined at
the state its predecessors leave, leaving a table $R_c$, and then retires rows and
emits $o$, all atomically.  Call a row \emph{ruled out by} $o$ when its output
does not \outrelbase $o$.  The event is \emph{legal} when $(i,o)\in R_c$ and every
row of $R_c$ ruled out by $o$ is \outrelpast by a retained row that \outrel $o$:
\begin{equation}
  (k,x)\in R_c\setminus R_c[\mathrm{out}\OutputGe o]
  \quad\Longrightarrow\quad
  \exists u\in R_c[\mathrm{out}\OutputGe o](k).\ x\OutputOrd u.
  \label{eq:lifted-validity}
\end{equation}
The event then retires those \outrelpast rows and ends at
$(i,R_c[\mathrm{out}\OutputGe o])$.
\end{definition}

This lifts Definition~\ref{def:output-event}.  With one row per input, a
ruled-out row has no other row at its input to \outrelbase it, so legality requires
that the commitments themselves leave only rows \outrelpart $o$, which is
Equation~\ref{eq:supported-output-action}.  With several rows per input, the
current row must now be retained explicitly, since other rows at $i$ may
remain.

Which rows must a legal event remove by commitment?  Emitting $o$ rules out
every row outside $R[\mathrm{out}\OutputGe o]$, but those rows need not all be
handled in the same way.  Some lie at inputs with no row \outrelpart $o$ and
require sealing the input, some can be retired because another row at the same
input \outrel them, and the rest require a binding choice among
outputs.  Accordingly, the ruled-out rows fall into three classes: the rows at
the inputs in $K_o$, and the rows in $D_o$ and $U_o$, where
\begin{align}
  K_o&=\mathrm{in}(R)\setminus\mathrm{in}(R[\mathrm{out}\OutputGe o]),
      \label{eq:seal-inputs}\\
  D_o&=\{(k,x)\in R\setminus R[\mathrm{out}\OutputGe o]:
          \exists u\in R[\mathrm{out}\OutputGe o](k).\ x\OutputOrd u\},
      \label{eq:output-retirements}\\
  U_o&=(R\setminus R[\mathrm{out}\OutputGe o])
       \setminus\bigl(D_o\cup R[\mathrm{in}\in K_o]\bigr).
      \label{eq:choice-removals}
\end{align}

\begin{definition}[Output retirement]
\label{def:output-retirement}
The \emph{output retirements} for $o$ at $(i,R)$ are the rows in $D_o$: rows
ruled out by $o$ but \outrelpast by a row at the same input that \outrel $o$.
\end{definition}

Rows at inputs in $K_o$ require a \emph{seal}, which removes every row at those
inputs.  Rows in $U_o$ are conflicts with $o$ that no row \outrelpart $o$ at
their input \outrel, and require a
\emph{choice}, which removes some outputs at an input while leaving it legal.
Every removed row thus has one of three causes: an input event removes rows that
can no longer happen, an output retirement removes rows \outrelpast by a row the
event keeps at the same input, and a commitment removes rows that could still
happen and that no remaining row at the same input \outrel.  Equation~\ref{eq:commitment-excludes} is judged at the
table a commitment leaves, so a row removed together with every row that
\outrel it counts as a commitment's removal, not a retirement.
Table~\ref{tab:removal-classes} summarizes the three classes.

For each $o\in O$, the \emph{canonical seal commitment} $s_o$, lifting
Definition~\ref{def:canonical-commitment-basis}, and the
\emph{canonical choice commitment} $c_o$ are the partial functions
\begin{equation}
  s_o(i,R)=\bigl(i,\ R\setminus R[\mathrm{in}\in K_o]\bigr),
  \qquad
  c_o(i,R)=\bigl(i,\ R\setminus U_o\bigr),
  \label{eq:canonical-seal-commitment-relational}
\end{equation}
where $s_o$ is defined at every state with $o\in R(i)$ and
$K_o\neq\varnothing$, and $c_o$ at every state with $o\in R(i)$,
$K_o=\varnothing$, and $U_o\neq\varnothing$.  The canonical commitment basis is
exactly
\begin{equation}
  \mathcal B_S
    =\{s_o:o\in O,\ \operatorname{dom}(s_o)\neq\varnothing\}
     \cup
     \{c_o:o\in O,\ \operatorname{dom}(c_o)\neq\varnothing\}.
  \label{eq:canonical-commitment-basis-relational}
\end{equation}
Both are commitments: no row either removes is \outrelpast by a row it keeps
(Equation~\ref{eq:commitment-excludes}).  The seal $s_o$ removes every row at
the inputs in $K_o$, so nothing remains there to \outrelbase a removed row.  For
$c_o$, suppose some $x\in U_o$ at input $k$ were \outrelpast by a row $y$ that
$c_o$ leaves at $k$.  Either $y$ \outrel $o$, or $y\in D_o$ and is \outrelpast by
a row \outrelpart $o$; by transitivity $x$ is then \outrelpast by a row \outrelpart
$o$, so $x\in D_o$, a contradiction.  Moreover, $c_o$ only chooses: a row of
$U_o$ at $k$ lies outside $K_o$, so some row at $k$ \outrel $o$ and survives.
With one row per input, $D_o$ and $U_o$ are empty and $s_o$ and $\mathcal B_S$
are those of Definition~\ref{def:canonical-commitment-basis}; canonical runs
now use this lifted basis.  Let $\kappa_o$ be the sequence that applies $s_o$ when
$K_o\neq\varnothing$, then $c_o$ when $U_o\neq\varnothing$, so $\kappa_o$ is
one of $\varepsilon$, $s_o$, $c_o$, or $s_o\,c_o$.
The \emph{canonical event} is $\Out{\kappa_o}{o}$: it applies $\kappa_o$, then
retires $D_o$ and emits $o$.\footnote{Here $K_o$, $D_o$, and $U_o$ are computed at the
state where the event starts.  Since $s_o$ removes only rows at inputs in
$K_o$, recomputing them after $s_o$ gives $K_o=\varnothing$ and the same $D_o$
and $U_o$, so $c_o$ is defined there whenever $U_o\neq\varnothing$.}

In Figure~\ref{fig:ambiguity-frames}(f), emitting $[A,B]$ places $[B,A]$ in
$U_o$: no row at $\{A,B\}$ \outrel both, so the event makes a choice.  In
panel~(g), the two removed route
sets are in $D_o$, each \outrelpast by a retained route set, so the event retires
them without commitment.

\begin{lemma}[Lifted containment, canonical support, and commitment-free events]
\label{lem:canonical-commitment-normal-form}
Let $(i,R)$ be a state and $o\in R(i)$.
\begin{enumerate}
  \item Every legal output event $\Out{\gamma}{o}$ takes $(i,R)$ to some $(i,R')$ with
        $R'\subseteq R[\mathrm{out}\OutputGe o]$, and removes the rows at
        inputs in $K_o$ and the rows in $U_o$ by commitment.
  \item The canonical event $\Out{\kappa_o}{o}$ is legal and takes $(i,R)$ to
        $(i,R[\mathrm{out}\OutputGe o])$.
  \item If $\Out{\varepsilon}{o}$ is legal, it takes $(i,R)$
        to $(i,R[\mathrm{out}\OutputGe o])$.
\end{enumerate}
\end{lemma}

\begin{proof}
(1) A legal event ends at $R_c[\mathrm{out}\OutputGe o]\subseteq
R[\mathrm{out}\OutputGe o]$, since its commitments only remove rows.  A row at
$k\in K_o$, or in $U_o$, has no \outrelpart row in $R[\mathrm{out}\OutputGe
o](k)$, and hence none in $R_c[\mathrm{out}\OutputGe o](k)$; it cannot be
retired, so a legal event must remove it by commitment.  (2) The canonical
commitments remove exactly the rows at inputs in $K_o$ and the rows in $U_o$, all
of them ruled out by $o$, so $R_c[\mathrm{out}\OutputGe o]=R[\mathrm{out}\OutputGe
o]$, which contains $(i,o)$.  Every remaining ruled-out row is in $D_o$, and its
\outrelpart row lies at an input outside $K_o$ and is not in $U_o$, so it
survives the commitments.  The event is therefore legal and ends at
$R[\mathrm{out}\OutputGe o]$.  (3) With no commitment, $R_c=R$, and a legal
event ends at $R[\mathrm{out}\OutputGe o]$.
\end{proof}

The canonical basis uses only seals and choices.  That is not a design decision:
no commitment can do anything else, and every system's runs are contained in
canonical runs that use only the canonical seals and choices.

\begin{proposition}[Commitments seal inputs or choose outputs]
\label{prop:seal-or-choose}
\leavevmode
\begin{enumerate}
  \item At each input where a commitment removes rows of the state it is
        applied to, it either removes every row, \emph{sealing} that input, or
        removes some outputs and keeps others, \emph{choosing} among them.
  \item Every run under any commitment basis is equivalent to a canonical run
        that keeps at least as many rows after each event and whose only
        commitments are the seals $s_o$ and the choices $c_o$.
  \item In a functional specification every commitment only seals.
\end{enumerate}
\end{proposition}

\begin{proof}
(1) At an input $k$, either no row remains or some does.  (2) Canonical
equivalents (Lemma~\ref{lem:canonical-equivalent}) give the run, and by the
check above $s_o$ only seals and $c_o$ only chooses.  (3) Each fiber has one row,
so removing a row at $k$ removes every row there.
\end{proof}

So the effect of any coordination mechanism---a lock, a timestamp, an agreement
protocol---is contained in a combination of seals and choices.  One subtlety:
$c_o$ acts at every \indesc of the current input, not only at it, so a choice
made now also constrains the choices still open at later inputs.  That is what a
promise is: once $o$ is emitted, later outputs must \outrelbase it.

Because each commitment acts on a given state, the classification is
unambiguous.  A seal may remove the last rows that earlier choices left at an
input; attributing the seal across that sequence is a question of provenance,
which this paper does not pursue.

Definition~\ref{def:exposable} applies unchanged: $o$ is exposable when
$\Out{\varepsilon}{o}$ is legal, though that event may still retire
\outrelpast rows.  The exposure test lifts as well:

\begin{proposition}[Lifted exposure test]
\label{prop:exposability}
An output $o\in R(i)$ is exposable at $(i,R)$ if and only if, for every legal
$j\InputGe i$ and $x\in R(j)$, some $u\in R(j)$ \outrel both:
\begin{equation}
  o\OutputOrd u
  \qquad\text{and}\qquad
  x\OutputOrd u.
  \label{eq:safe-exposure}
\end{equation}
\end{proposition}

\begin{proof}
A commitment-free event has $R_c=R$, which contains $(i,o)$.  By
Equation~\ref{eq:lifted-validity} it is legal exactly when every ruled-out row
$(j,x)$ is \outrelpast by some row $(j,u)$ \outrelpart $o$.  Rows that already
\outrelbase $o$ satisfy the stated test with $u=x$, so legality is exactly the
stated test.
\end{proof}

This test marks the commitment boundary: if it fails, every legal
$\Out{\gamma}{o}$ has $\gamma\neq\varepsilon$.

\subsection{Lifted executions and consistency}
\label{sec:relational-executions}

Lemma~\ref{lem:canonical-commitment-normal-form} and
Proposition~\ref{prop:exposability} re-establish, for lifted output events, the
facts of Proposition~\ref{prop:canonical-output-preservation}.  Specification
states, input events, runs, canonical runs, commitment-free runs, and
Consistency are defined as before, and the results of
Section~\ref{sec:determination} used output events only through those facts.
They therefore lift unchanged: canonical equivalents
(Lemma~\ref{lem:canonical-equivalent}), the rows remaining after a canonical
run (Lemma~\ref{lem:run-residual}), the fact that commitment-free runs are
canonical, and the survivor test (Proposition~\ref{prop:confluence}).  So does
the distributed reading of Consistency
(Proposition~\ref{prop:distributed-consistency}).  With them, Consistency
reduces to the common-\indesc condition.

\begin{theorem}[Common-\indesc characterization]
\label{thm:common-refinement}
An ordered specification is consistent if and only if it satisfies the
common-\indesc condition.
\end{theorem}

\begin{proof}[Proof sketch]
If the condition holds, a common refinement $u\in S(j)$ of everything emitted survives in every run (Lemma~\ref{lem:run-residual}); conversely, runs that each emit one row's output must share a surviving row at $j$.  Full proof in Appendix~\ref{app:proofs}.
\end{proof}

The same condition governs exposability.

\begin{proposition}[Exposure boundary]
\label{prop:exposure-boundary}
An ordered specification satisfies the common-\indesc condition if and only
if every output at every state reachable without commitment is exposable.
\end{proposition}

\begin{proof}[Proof sketch]
Consistency supplies the refining row the exposure test needs; conversely, applying the exposure test one row at a time builds a common refinement.  Full proof in Appendix~\ref{app:proofs}.
\end{proof}

With one output per input the common-\indesc condition is monotonicity, so
Theorem~\ref{thm:common-refinement} and Proposition~\ref{prop:exposure-boundary}
specialize to Functional CALM (Theorem~\ref{thm:functional-calm}) and
Proposition~\ref{prop:functional-exposure-boundary}.  One result used the
functional dependency itself and does not lift: the surviving row in the
survivor test need not be unique, so neither is the reconciled state, and
Corollary~\ref{cor:state-by-input} fails; Section~\ref{sec:complete-calm}
returns to this.  In place of the functional reduction to monotonicity,
Proposition~\ref{prop:lifted-monotonicity-decomposition} identifies the
common-\indesc condition with Lifted Monotonicity: it is form~(3).  Lifted
Monotonicity is therefore the lifted form of functional monotonicity in a
precise sense: both are the common-\indesc condition, read for one output
per input or for many.  Section~\ref{sec:complete-calm} assembles Complete
CALM from these parts.
