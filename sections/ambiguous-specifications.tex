\section{Complete CALM}
\label{sec:ambiguous-specifications}

We now allow a fiber to contain several outputs.  The monotonicity property we want to test as input
\ingrows from $i$ to $j\InputGe i$ must be lifted to sets: can \emph{some}
output in the fiber at $j$ \outrelbase \emph{whatever} outputs runs emit at $i$?
In addition to seal commitments on inputs, we now have a second kind of commitment: \emph{choosing}
among permitted outputs.  Section~\ref{sec:ambiguity-story} introduces the issue by
example.  Section~\ref{sec:relational-specifications} defines relational
specifications, and Section~\ref{sec:lifted-monotonicity} Lifted
Monotonicity.  Section~\ref{sec:safe-exposure} lifts
output events and classifies what they remove, and
Section~\ref{sec:relational-executions} shows that the run-level results of
Section~\ref{sec:determination} carry over and proves Complete CALM.

\subsection{Output choice by example}
\label{sec:ambiguity-story}

several outputs in one fiber.  Transaction ordering requires a choice
between incompatible serialization orders.  Traceroute observations, by
contrast, can all be \outrelpast by a larger route set.

\paragraph{Output choice and directedness.} The examples differ in what happens
to alternative outputs when one is emitted.  In panel~(f), neither
serialization order \outrel the other, so emitting one requires a
\emph{choice commitment} that removes the other while the input stays legal:
emitting $[A,B]$ chooses it over $[B,A]$.  In panel~(g), larger route sets \outrelbase both the
emitted observation and the outputs of the rows it removes.  We call such
removal an \emph{output retirement}
(Definition~\ref{def:output-retirement}); every removed output is
\outrelpast by a remaining one, so emitting the route observation needs no
commitment: it is \emph{exposable}.  

An output event can thus remove rows in three ways: by sealing inputs, as in
Section~\ref{sec:functional-calm}; by retiring outputs, as in panel~(g); or by
choosing among outputs, as in panel~(f).  The atomic event
$\mathsf{output}(o)$ does whichever of these $o$ requires, then emits $o$;
sealing and choosing are commitments, retiring is not.

In Figure~\ref{fig:ambiguity-frames}, serialization requires commitment; traceroute avoids it.
The difference between them is the order-theoretic concept of a \emph{directed} fiber:
every finite set of outputs in a given fiber has a common \outnoun in that fiber.
Directedness at a single input is not sufficient, however;
we must also \outrelbase prior outputs as input \ingrows. \emph{Lifted Monotonicity}
combines the requirements: as input \ingrows from $i$ to $j$, some output
in the fiber at $j$ \outrel whatever outputs runs emit at $i$.  Equivalently,
outputs emitted at inputs with a common \indesc $j$ must have a common
\outnoun in the fiber at $j$: the same test as in Section~\ref{sec:election-story}, but
with many outputs per input.  Two transaction scheduling runs that emit $[A,B]$ and $[B,A]$ fail it;
two traceroute runs that emit different route sets pass it, since their union
survives in both.

Different systems can realize the same choice differently. For example two transaction systems 
may achieve the same schedule, one by
taking a lock and the other by assigning a timestamp; Section~\ref{sec:coordination} addresses
such systems.

\subsection{Relational specifications and states}
\label{sec:relational-specifications}

We begin with our most general definition of a specification, which admits
ambiguity of output.
\begin{definition}[Ordered relational specification]
\label{def:relational-specification}
An \emph{ordered relational specification} is
        \begin{equation}
  \Spec=(I,\InputOrd,O,\OutputOrd,S),
  \qquad S\subseteq I\times O,
  \label{eq:relational-specification}
        \end{equation}
where $(I,\InputOrd)$ and $(O,\OutputOrd)$ are partially ordered sets and $S$
is total on $I$: every input appears in at least one row.  A row $(i,o)\in S$
says that output $o$ is permitted at input $i$.  The fiber
        \begin{equation}
  \fiber{i}=\{o\in O:(i,o)\in S\}
  \label{eq:fiber}
        \end{equation}
of Section~\ref{sec:functional-specifications} may now contain several
outputs; the specification is \emph{ambiguous} when some fiber does.  A
functional specification is the special case $\fiber{i}=\{f(i)\}$.
\end{definition}

Specification states and input events
(Sections~\ref{sec:functional-specifications} and~\ref{sec:functional-events})
apply unchanged to relational tables; Section~\ref{sec:safe-exposure} lifts
output events.

\subsection{Lifted Monotonicity}
\label{sec:lifted-monotonicity}

The examples from the start of this section pose the next question: as input
\ingrows from $i$ to $j$, can some output in the fiber at $j$ \outrelbase
whatever outputs runs emit at $i$?  Two things can go wrong.  A
\emph{stranded output} is an output in the fiber at $i$ with no \outnoun in
the fiber at some \indesc $j$.  An \emph{incompatible pair} is two outputs in
the fiber at $i$ with no common \outnoun there.  We rule out
each in turn, combine the two, and then restate the result in the form runs
need.

Ruling out stranded outputs asks that every output keep some \outnoun as
input \ingrows.

\begin{definition}[Relational Monotonicity]
\label{def:relational-monotonicity}
An ordered relational specification satisfies \emph{Relational Monotonicity}
when every output keeps some \outnoun as input \ingrows:
        \begin{equation}
  i\InputOrd j,\ o\in\fiber{i}
  \quad\Longrightarrow\quad
  \exists u\in\fiber{j}:\ o\OutputOrd u.
  \label{eq:relational-monotonicity}
        \end{equation}
\end{definition}

For singleton fibers this is functional monotonicity,
Equation~\ref{eq:functional-monotonicity}.  It treats each output separately,
so it does not rule out incompatible pairs, which concern several outputs in
one fiber.
For a set $F\subseteq O$ of outputs, outputs $o_1,\ldots,o_k$ are
\emph{compatible in $F$} if some $u\in F$ \outrel all of them, and
\emph{incompatible in $F$} otherwise.

Ruling out incompatible pairs asks that every finite set of outputs in a
fiber be compatible there.

\begin{definition}[Directed fiber, Directed Outputs]
\label{def:fiber-directedness}
A fiber $F\subseteq O$ is \emph{directed} when every nonempty finite
$X\subseteq F$ is compatible in $F$.  An ordered relational specification has
\emph{Directed Outputs} when every fiber $\fiber{i}$ is directed.
\end{definition}

A singleton fiber is trivially directed.  As with common \indescs of inputs
(Section~\ref{sec:functional-specifications}), a common \outnoun need not be
least: directedness requires some upper bound within the fiber for each finite
set, not a least one or a fixed merge operator, so it is weaker than a
join-semilattice.  For example, the fiber
$\{\{a\},\{b\},\{a,b,c\},\{a,b,d\},\{a,b,c,d\}\}$ under inclusion is directed,
since $\{a,b,c,d\}$ \outrel every member, yet $\{a\}$ and $\{b\}$ have two
incomparable minimal common \outnouns.  Compatibility likewise does not require
comparability: two incomparable outputs may have a third output in the fiber
that \outrel both, as $\{a,b,c\}$ and $\{a,b,d\}$ do in the fiber above.  Thus
the traceroute fiber is directed: the union of any finite set of route sets in
it is again in the fiber and refines each of them. The two transaction orders in
Figure 5(f), by contrast, are incompatible.

\paragraph{Lifted Monotonicity.}
To state both requirements at once, lift $\OutputOrd$ to sets.  For nonempty
$A,B\subseteq O$, define
        \begin{equation}
  A\LiftedOrd B
  \;\Longleftrightarrow\;
  \text{every nonempty finite }X\subseteq A\text{ is compatible in }B,
  \label{eq:joint-output-order}
        \end{equation}
the \emph{joint lift} of $\OutputOrd$.  Read it with $A=\fiber{i}$ and
$B=\fiber{j}$ for $i\InputOrd j$.  When $X$ is a single output $o$, it asks
that $o$ have a \outnoun in $\fiber{j}$, which rules out stranded outputs.  When $X$
holds several outputs, it asks that they have a common \outnoun in $\fiber{j}$; with
$j=i$, this rules out incompatible pairs.

\begin{definition}[Lifted Monotonicity, monotone specification]
\label{def:lifted-monotonicity}
An ordered relational specification satisfies \emph{Lifted Monotonicity}, and
is called \emph{monotone}, when the mapping $i\mapsto\fiber{i}$ is monotone
under the joint lift:
        \begin{equation}
  i\InputOrd j
  \quad\Longrightarrow\quad
  \fiber{i}\LiftedOrd\fiber{j}.
  \label{eq:lifted-monotonicity}
        \end{equation}
\end{definition}

With singleton fibers it is functional monotonicity
(Definition~\ref{def:functional-monotonicity}).  As the reading above shows,
it implies Relational Monotonicity and Directed Outputs; conversely, for
$i\InputOrd j$ and finite nonempty $X\subseteq\fiber{i}$, Relational
Monotonicity gives each $x\in X$ a \outnoun in $\fiber{j}$, and Directed
Outputs gives those a common \outnoun in $\fiber{j}$.  So Lifted Monotonicity
holds exactly when both do.

\paragraph{The common-\indesc condition.}
Runs emit outputs at different inputs and meet at a common \indesc, but Lifted
Monotonicity compares the fiber at an input with the fibers at its \indescs.  An
equivalent condition compares outputs across inputs directly.

\begin{definition}[Common-\indesc condition]
\label{def:common-refinement-condition}
An ordered specification satisfies the \emph{common-\indesc condition} when,
for every finite set of rows $(i_1,o_1),\ldots,(i_k,o_k)$ of $S$ and every
common \indesc $j$ of $i_1,\ldots,i_k$, some $u\in S(j)$ \outrel every
$o_r$.
\end{definition}

The inputs $i_r$ need not be comparable, because different runs meet only at a
common \indesc.  For the empty set of rows the condition asks only that
$S(j)$ be nonempty, which totality guarantees.

\begin{proposition}[Common-\indesc form of Lifted Monotonicity]
\label{prop:lifted-monotonicity-decomposition}
An ordered relational specification satisfies Lifted Monotonicity if and only
if it satisfies the common-\indesc condition.
\end{proposition}

\begin{proof}
Suppose Lifted Monotonicity, and let rows $(i_r,o_r)$ have common \indesc
$j$.  For the empty family, totality gives $\fiber{j}\neq\varnothing$.
Otherwise, since $i_r\InputOrd j$, Relational Monotonicity gives, for each
$r$, a $u_r\in\fiber{j}$ with $o_r\OutputOrd u_r$.  The $u_r$ all lie in the
one fiber $\fiber{j}$, which is directed, so some $u\in\fiber{j}$ \outrel
every $u_r$, hence every $o_r$.  Conversely, let $i\InputOrd j$ and
$X\subseteq\fiber{i}$ be nonempty and finite.  The rows $\{(i,x):x\in X\}$
have common \indesc $j$, so some $u\in\fiber{j}$ \outrel all of $X$; that is
$\fiber{i}\LiftedOrd\fiber{j}$.
\end{proof}

\subsection{Lifted output events}
\label{sec:safe-exposure}

Lifted Monotonicity is a property of the table.  We now return to execution.
In the functional case an output event either removes nothing or seals inputs
(Definition~\ref{def:output-event}).  With several rows at one input, emitting
$o$ can also retire a \outrelpast row or choose among outputs, as the examples
of Section~\ref{sec:ambiguity-story} showed.  We lift output events to cover
all three.

Fix a state $(i,R)$ and an output $o\in R(i)$.  A row is \emph{ruled out by}
$o$ when its output does not \outrelbase $o$.  The ruled-out rows fall into
three disjoint classes, by how they can be removed:
\begin{align}
  \Sealed_o&=\{(k,x)\in R:\ k\notin\mathrm{in}(R[\mathrm{out}\OutputGe o])\},
      \label{eq:seal-inputs}\\
  \Retired_o&=\{(k,x)\in R\setminus R[\mathrm{out}\OutputGe o]:\notag\\
    &\qquad\quad x\OutputOrd u\text{ for some }u\in R[\mathrm{out}\OutputGe o](k)\},
      \label{eq:output-retirements}\\
  \Rejected_o&=(R\setminus R[\mathrm{out}\OutputGe o])
       \setminus(\Sealed_o\cup\Retired_o).
      \label{eq:choice-removals}
\end{align}

\begin{definition}[Lifted output event, seal, output retirement, choice]
\label{def:lifted-output-event}
\label{def:output-retirement}
Let $(i,R)$ be a state and $o\in R(i)$.  The \emph{output event}
$\mathsf{output}(o)$ keeps exactly the rows whose outputs \outrelbase $o$ and
emits $o$, atomically, ending at $(i,R[\mathrm{out}\OutputGe o])$ as in
Equation~\ref{eq:output-action}.  When $\Sealed_o\neq\varnothing$ it applies the \emph{seal} $s_o$.  It removes
the rows in $\Retired_o$, each \outrelpast by a kept row at the same input, by
\emph{output retirement}, which is not a commitment.  When
$\Rejected_o\neq\varnothing$ it applies the \emph{choice} $c_o$.  The seal and
the choice are \emph{commitments}:
\begin{equation}
  s_o(i,R)=\bigl(i,\ R\setminus\Sealed_o\bigr),
  \qquad
  c_o(i,R)=\bigl(i,\ R\setminus\Rejected_o\bigr).
  \label{eq:canonical-seal-commitment-relational}
\end{equation}
\end{definition}

In Figure~\ref{fig:ambiguity-frames}(f), emitting $[A,B]$ places $[B,A]$ in
$\Rejected_o$: no row at $\{A,B\}$ \outrel both, so the event makes a choice.  In
panel~(g), the two removed route
sets are in $\Retired_o$, each \outrelpast by a retained route set, so the event retires
them without commitment.

The three sets are disjoint, and removing the rows of either commitment leaves
the other sets unchanged, so the event may apply $s_o$ and $c_o$ in either
order.  The choice commitment only narrows fibers: at each input it touches, some row
that \outrel $o$ survives.  With one row per input, $\Retired_o$ and $\Rejected_o$
are empty; this is the functional output event of
Definition~\ref{def:output-event}.  Apart from these, a row leaves the
remainder table only by input retirement (Section~\ref{sec:functional-events}).

Exposability lifts with the event: $o$ is exposable when $\mathsf{output}(o)$
applies no commitment, that is, when $\Sealed_o$ and $\Rejected_o$ are empty, though the
event may still retire the rows in $\Retired_o$.  The exposure test lifts as well:

\begin{proposition}[Lifted exposure test]
\label{prop:exposability}
An output $o\in R(i)$ is exposable at $(i,R)$ if and only if, for every legal
$j\InputGe i$ and $x\in R(j)$, some $u\in R(j)$ \outrel both:
\begin{equation}
  o\OutputOrd u
  \qquad\text{and}\qquad
  x\OutputOrd u.
  \label{eq:safe-exposure}
\end{equation}
\end{proposition}

\begin{proof}
The event $\mathsf{output}(o)$ applies no commitment exactly when every
ruled-out row $(j,x)$ lies in $\Retired_o$, that is, is \outrelpast by some row
$(j,u)$ \outrelpart $o$.  Rows that already \outrelbase $o$ satisfy the stated
test with $u=x$, so this is exactly the stated test.
\end{proof}

This test marks the commitment boundary: if it fails, emitting $o$ requires a
seal or a choice.

\subsection{The Complete CALM theorem}
\label{sec:relational-executions}
\label{sec:complete-calm-theorem}

A lifted output event ends at $(i,R[\mathrm{out}\OutputGe o])$, exactly as in
Equation~\ref{eq:output-action}.  Specification states, input events, runs,
commitment-free runs, and consistency are defined as before, and the results
of Section~\ref{sec:determination} used output events only through that
equation.  They therefore lift unchanged: the rows remaining after a run
(Lemma~\ref{lem:run-residual}) and the survivor test
(Proposition~\ref{prop:confluence}).  With them, consistency
reduces to Lifted Monotonicity, just as it reduced to monotonicity for
functions.

\begin{theorem}[Complete CALM]
\label{thm:complete-calm}
\label{thm:common-refinement}
An ordered specification is consistent if and only if it satisfies Lifted
Monotonicity, equivalently the common-\indesc condition.
\end{theorem}

\begin{proof}[Proof sketch]
By Proposition~\ref{prop:lifted-monotonicity-decomposition} it suffices to
treat the common-\indesc condition.  If it holds, a common refinement $u\in S(j)$ of everything emitted survives in every run (Lemma~\ref{lem:run-residual}); conversely, runs that each emit one row's output must share a surviving row at $j$.  Full proof in Appendix~\ref{app:proofs}.
\end{proof}

The name CALM, for Consistency As Logical Monotonicity, tied the idea to a
logic language.  The condition that characterizes consistency is instead a
property of the specification: Lifted Monotonicity, which for a function is
ordinary monotonicity.  Section~\ref{sec:distributed-consistency} shows that
Functional CALM and Complete CALM both hold for distributed histories.

The same condition governs exposability.

\begin{proposition}[Exposure boundary]
\label{prop:exposure-boundary}
An ordered specification satisfies the common-\indesc condition if and only
if every output at every state reachable without commitment is exposable.
\end{proposition}

\begin{proof}[Proof sketch]
If the common-\indesc condition holds, the specification is consistent
(Theorem~\ref{thm:common-refinement}), and the survivor test
(Proposition~\ref{prop:confluence}) supplies the row the lifted exposure test
(Proposition~\ref{prop:exposability}) requires.  Conversely, applying the
lifted exposure test at canonical states, one row at a time, builds the common
\outnoun the common-\indesc condition asks for.  Full proof in
Appendix~\ref{app:proofs}.
\end{proof}

With one output per input, Lifted Monotonicity and the common-\indesc
condition are both monotonicity, so Complete CALM and
Proposition~\ref{prop:exposure-boundary} reduce to Functional CALM and
Proposition~\ref{prop:functional-exposure-boundary}.  Lifted Monotonicity is
the lifted form of functional monotonicity in a precise sense: both are the
common-\indesc condition, read for one output per input or for many.

One functional result does not carry over.  In a consistent functional
specification, every run ending at input $i$ is in the canonical state
$\sigma_S(i)$ (Corollary~\ref{cor:state-by-input}).  With several outputs per
input, runs that reach the same input can keep different rows: in
Figure~\ref{fig:ambiguity-frames}(g), a run that emitted
$\{s{\to}\texttt{s1}\}$ has retired the route sets that omit it, while a run
that emitted nothing keeps them.  The state then depends on the outputs
emitted, not only on the input; Section~\ref{sec:coordination-def} returns
to this.

systems that realize these specifications, and coordination.
