\section{Ambiguous Specifications and Lifted Monotonicity}
\label{sec:ambiguous-specifications}

In this section we drop the functional dependency, allowing a fiber to
contain several outputs.  The monotonicity property we want to test as input
grows from $i$ to $j\InputGe i$ must now be lifted to sets: can \emph{some}
output permitted at $j$ \outrelbase \emph{whatever} outputs runs emit at $i$?
In addition to seal commitments on inputs, we now have a second kind of commitment: \emph{choosing}
among permitted outputs.  Section~\ref{sec:ambiguity-story} introduces the issue by
example.  Section~\ref{sec:relational-specifications} defines relational
specifications, and Section~\ref{sec:lifted-monotonicity} Lifted
Monotonicity.  Section~\ref{sec:safe-exposure} lifts
output events and classifies what they remove, and
Section~\ref{sec:relational-executions} shows that the run-level results of
Section~\ref{sec:determination} carry over and characterizes consistency by a
condition on the table.

\label{sec:ambiguity-story}

several outputs at the same input.  Transaction ordering requires a choice
between incompatible serialization orders.  Traceroute observations, by
contrast, can all be \outrelpast by a larger route set.

\paragraph{Output choice and directedness.} The examples differ in what happens
to alternative outputs when one is emitted.  In panel~(f), neither
serialization order \outrel the other, so emitting one requires a
\emph{choice commitment} that removes the other while the input stays legal:
emitting $[A,B]$ chooses it over $[B,A]$.  In panel~(g), larger route sets \outrelbase both the
emitted observation and the outputs of the rows it removes.  We call such
removal an \emph{output retirement}
(Definition~\ref{def:output-retirement}); every removed output is
\outrelpast by a remaining one, so emitting the route observation needs no
commitment: it is \emph{exposable}.  

An output event can thus remove rows in three ways: by sealing inputs, as in
Section~\ref{sec:functional-calm}; by choosing among outputs, as in
panel~(f); or by retiring outputs, as in panel~(g).  The atomic event
$\mathsf{output}(o)$ does whichever of these $o$ requires, then emits $o$;
only the first two are commitments.

In Figure~\ref{fig:ambiguity-frames}, serialization requires commitment; traceroute avoids it.
The difference between them is the order-theoretic concept of a \emph{directed} fiber:
every finite set of outputs in a given fiber has a common \outnoun in that fiber.
Directedness at a single input is not sufficient, however;
we must also \outrelbase prior outputs as input \ingrows. \emph{Lifted Monotonicity}
combines the requirements: as input \ingrows from $i$ to $j$, some output
permitted at $j$ \outrel whatever outputs runs emit at $i$.  Equivalently,
outputs emitted at inputs with a common \indesc $j$ must have a common
\outnoun permitted at $j$: the same test as in Section~\ref{sec:election-story}, but
with many outputs per input.  Two transaction scheduling runs that emit $[A,B]$ and $[B,A]$ fail it;
two traceroute runs that emit different route sets pass it, since their union
survives in both.

Different systems can realize the same choice differently. For example two transaction systems 
may achieve the same schedule, one by
taking a lock and the other by assigning a timestamp; Section~\ref{sec:coordination} addresses
such systems.

\subsection{Relational specifications}
\label{sec:relational-specifications}

We begin with our most general definition of a specification, which admits
ambiguity of output.
\begin{definition}[Ordered relational specification]
\label{def:relational-specification}
An \emph{ordered relational specification} is
        \begin{equation}
  \Spec=(I,\InputOrd,O,\OutputOrd,S),
  \qquad S\subseteq I\times O,
  \label{eq:relational-specification}
        \end{equation}
where $(I,\InputOrd)$ and $(O,\OutputOrd)$ are partially ordered sets and $S$
is total on $I$: every input appears in at least one row.  A row $(i,o)\in S$
says that output $o$ is permitted at input $i$.  The fiber
        \begin{equation}
  \fiber{i}=\{o\in O:(i,o)\in S\}
  \label{eq:fiber}
        \end{equation}
of Section~\ref{sec:functional-specifications} may now contain several
outputs; the specification is \emph{ambiguous} when some fiber does.  A
functional specification is the special case $\fiber{i}=\{f(i)\}$.
\end{definition}

Specification states and input events
(Sections~\ref{sec:functional-specifications} and~\ref{sec:functional-events})
apply unchanged to relational tables; Section~\ref{sec:safe-exposure} lifts
output events.

\subsection{Lifted Monotonicity}
\label{sec:lifted-monotonicity}

The examples from the start of this section pose the next question: as input
\ingrows from $i$ to $j$, can some output permitted at $j$ \outrelbase
whatever outputs runs emit at $i$?  Two things can go wrong: an output at $i$
has no \outnoun in the fiber of some \indesc $j$, or two different outputs permitted at
$i$ have no common \outnoun in the fiber of $i$.  We define each, then combine them.

\begin{definition}[Relational Monotonicity]
\label{def:relational-monotonicity}
An ordered relational specification satisfies \emph{Relational Monotonicity}
when every output keeps some \outnoun as input \ingrows:
        \begin{equation}
  i\InputOrd j,\ o\in\fiber{i}
  \quad\Longrightarrow\quad
  \exists u\in\fiber{j}:\ o\OutputOrd u.
  \label{eq:relational-monotonicity}
        \end{equation}
\end{definition}

For singleton fibers this is functional monotonicity,
Equation~\ref{eq:functional-monotonicity}.  It treats each output separately.
% and does not say whether several outputs permitted at one input have a
% common \outnoun; Directed Outputs (Definition~\ref{def:fiber-directedness})
% addresses that question.

The next concern regards several outputs jointly.
For a set $F\subseteq O$ of outputs, outputs $o_1,\ldots,o_k$ are
\emph{compatible in $F$} if some $u\in F$ \outrel all of them, and
\emph{incompatible in $F$} otherwise; they are \emph{compatible at input $i$}
when they are compatible in the fiber $\fiber{i}$.

\begin{definition}[Directed fiber, Directed Outputs]
\label{def:fiber-directedness}
A fiber $F\subseteq O$ is \emph{directed} when every nonempty finite
$X\subseteq F$ is compatible in $F$.  An ordered relational specification has
\emph{Directed Outputs} when every fiber $\fiber{i}$ is directed.
\end{definition}

A singleton fiber is trivially directed.  As with common \indescs of inputs
(Section~\ref{sec:functional-specifications}), a common \outnoun need not be
least: directedness requires some upper bound within the fiber for each finite
set, not a least one or a fixed merge operator, so it is weaker than a
join-semilattice.  For example, the fiber
$\{\{a\},\{b\},\{a,b,c\},\{a,b,d\},\{a,b,c,d\}\}$ under inclusion is directed,
since $\{a,b,c,d\}$ \outrel every member, yet $\{a\}$ and $\{b\}$ have two
incomparable minimal common \outnouns.  Compatibility likewise does not require
comparability: two incomparable outputs may have a third output in the fiber
that \outrel both, as $\{a,b,c\}$ and $\{a,b,d\}$ do in the fiber above.  Thus
the traceroute fiber is directed: the union of any finite set of route sets in
it is again in the fiber and refines each of them. The two transaction orders in
Figure 5(f), by contrast, are incompatible.

\paragraph{Lifted Monotonicity.}

Relational Monotonicity gives each output a \outnoun at every \indesc of its
input; Directed Outputs gives each finite set within a fiber a common \outnoun.  The joint lift
expresses both.  For nonempty $A,B\subseteq O$, define
        \begin{equation}
  A\LiftedOrd B
  \;\Longleftrightarrow\;
  \text{every nonempty finite }X\subseteq A\text{ is compatible in }B,
  \label{eq:joint-output-order}
        \end{equation}
the \emph{joint lift} of $\OutputOrd$.  It contains both conditions.  When
$X=\{o\}$ is a single output of $A$, it asks that $o$ have a \outnoun in $B$:
with $A=\fiber{i}$ and $B=\fiber{j}$, this is Relational Monotonicity.  When
$X$ contains several outputs of $A$, it asks that they have a common
\outnoun in $B$: with $A=B$, this is directedness, so $A\LiftedOrd A$ holds
exactly when $A$ is directed.

\begin{definition}[Lifted Monotonicity, monotone specification]
\label{def:lifted-monotonicity}
An ordered relational specification satisfies \emph{Lifted Monotonicity}, and
is called \emph{monotone}, when the mapping $i\mapsto\fiber{i}$ is monotone
under the joint lift:
        \begin{equation}
  i\InputOrd j
  \quad\Longrightarrow\quad
  \fiber{i}\LiftedOrd\fiber{j}.
  \label{eq:lifted-monotonicity}
        \end{equation}
\end{definition}

With singleton fibers it is functional monotonicity
(Definition~\ref{def:functional-monotonicity}).  Runs, however, emit outputs
at different inputs and meet at a common \indesc, and neither form above
compares outputs across inputs directly.  The following condition has the form
runs need, comparing outputs emitted at different inputs, and is equivalent to
Lifted Monotonicity (Proposition~\ref{prop:lifted-monotonicity-decomposition}):

\begin{definition}[Common-\indesc condition]
\label{def:common-refinement-condition}
An ordered specification satisfies the \emph{common-\indesc condition} when,
for every finite set of rows $(i_1,o_1),\ldots,(i_k,o_k)$ of $S$ and every
common \indesc $j$ of $i_1,\ldots,i_k$, some $u\in S(j)$ \outrel every
$o_r$.
\end{definition}

The inputs $i_r$ need not be comparable, because different runs meet only at a
common \indesc.  For the empty set of rows the condition asks only that
$S(j)$ be nonempty, which totality guarantees.

The next proposition supplies
two forms used later: form~(2) separates the
across-input and within-fiber requirements, and form~(3) matches confluence by
allowing outputs from several inputs.

\begin{proposition}[Equivalent forms of Lifted Monotonicity]
\label{prop:lifted-monotonicity-decomposition}
For an ordered relational specification, the following are equivalent:
\begin{enumerate}
  \item Lifted Monotonicity: $i\InputOrd j$ implies
        $\fiber{i}\LiftedOrd\fiber{j}$;
  \item Relational Monotonicity and Directed Outputs;
  \item the common-\indesc condition
        (Definition~\ref{def:common-refinement-condition}): for every finite
        set of rows $(i_1,o_1),\ldots,(i_k,o_k)$ of $S$, the outputs
        $o_1,\ldots,o_k$ are compatible at every common \indesc of
          $i_1,\ldots,i_k$.
\end{enumerate}
\end{proposition}

\begin{proof}
(1) implies (2).  Taking $j=i$, $\fiber{i}\LiftedOrd\fiber{i}$ says that
$\fiber{i}$ is directed.  Taking $X=\{o\}$ for $o\in\fiber{i}$ and
$i\InputOrd j$ gives $u\in\fiber{j}$ with $o\OutputOrd u$, which is Relational
Monotonicity.

(2) implies (3).  Let rows $(i_r,o_r)$ have common \indesc $j$.  For the
empty family, totality gives $\fiber{j}\neq\varnothing$.  Otherwise, since
$i_r\InputOrd j$, Relational Monotonicity gives, for each $r$, a
$u_r\in\fiber{j}$ with $o_r\OutputOrd u_r$.  The $u_r$ now all lie in the one
fiber $\fiber{j}$, which is directed, so some $u\in\fiber{j}$ \outrel every
$u_r$, hence every $o_r$.

(3) implies (1).  Let $i\InputOrd j$ and $X\subseteq\fiber{i}$ be nonempty and
finite.  The rows $\{(i,x):x\in X\}$ have common \indesc $j$, so some
$u\in\fiber{j}$ \outrel all of $X$; that is $\fiber{i}\LiftedOrd\fiber{j}$.
\end{proof}

\subsection{Lifted output events}
\label{sec:safe-exposure}

The functional case has one row per input, so an output event either removes
nothing or seals a legal input.  With several rows at one input, emitting $o$
can also retire a \outrelpast row while keeping the row that \outrel it, or
make a binding choice among outputs.  We lift output events to this case.

Fix a state $(i,R)$ and an output $o\in R(i)$.  Call a row
\emph{ruled out by} $o$ when its output does not \outrelbase $o$.
Emitting $o$ rules out every row outside $R[\mathrm{out}\OutputGe o]$, but
those rows need not all be handled in the same way.  Some lie at inputs with no
row \outrelpart $o$ and require sealing the input, some can be retired because
another row at the same input \outrel them, and the rest require a binding
choice among outputs.  Accordingly, the ruled-out rows fall into three classes:
the rows at the inputs in $K_o$, and the rows in $D_o$ and $U_o$, where
\begin{align}
  K_o&=\mathrm{in}(R)\setminus\mathrm{in}(R[\mathrm{out}\OutputGe o]),
      \label{eq:seal-inputs}\\
  D_o&=\{(k,x)\in R\setminus R[\mathrm{out}\OutputGe o]:
          \exists u\in R[\mathrm{out}\OutputGe o](k).\ x\OutputOrd u\},
      \label{eq:output-retirements}\\
  U_o&=(R\setminus R[\mathrm{out}\OutputGe o])
       \setminus\bigl(D_o\cup R[\mathrm{in}\in K_o]\bigr).
      \label{eq:choice-removals}
\end{align}

\begin{definition}[Output retirement]
\label{def:output-retirement}
The \emph{output retirements} for $o$ at $(i,R)$ are the rows in $D_o$: rows
ruled out by $o$ but \outrelpast by a row at the same input that \outrel $o$.
\end{definition}

\begin{definition}[Lifted output event, seal, choice]
\label{def:lifted-output-event}
Let $(i,R)$ be a state and $o\in R(i)$.  The \emph{output event}
$\mathsf{output}(o)$ keeps exactly the rows whose outputs \outrelbase $o$ and
emits $o$, atomically, ending at $(i,R[\mathrm{out}\OutputGe o])$ as in
Equation~\ref{eq:output-action}.  It removes the ruled-out rows in three ways.
When $K_o\neq\varnothing$ it applies the \emph{seal} $s_o$, and when
$U_o\neq\varnothing$ the \emph{choice} $c_o$, two \emph{commitments}:
\begin{equation}
  s_o(i,R)=\bigl(i,\ R\setminus R[\mathrm{in}\in K_o]\bigr),
  \qquad
  c_o(i,R)=\bigl(i,\ R\setminus U_o\bigr).
  \label{eq:canonical-seal-commitment-relational}
\end{equation}
It removes the rows in $D_o$ by output retirement, which is not a commitment.
\end{definition}

The three sets are disjoint, so the event is well defined.  Removing the rows
at inputs in $K_o$ leaves $D_o$ and $U_o$ unchanged, and removing $U_o$ leaves
$K_o$ and $D_o$ unchanged, so the order in which the event applies $s_o$ and
$c_o$ does not matter.  The seal $s_o$
empties the fiber at each input in $K_o$, sealing it.  The choice $c_o$ removes
some outputs at each input it touches and keeps others: a row of $U_o$ at $k$
lies outside $K_o$, so some row at $k$ \outrel $o$ and survives.  With one row
per input, $D_o$ and $U_o$ are empty and this is
Definition~\ref{def:output-event}.  Because $c_o$ acts at every \indesc of the
current input, not only at it, a choice made now also constrains the choices
still open at later inputs.  That is what a promise is: once $o$ is emitted,
later outputs must \outrelbase it.

Rows removed by an input event can no longer happen; rows ruled out by an
output fall into the three classes of Table~\ref{tab:removal-classes}.

In Figure~\ref{fig:ambiguity-frames}(f), emitting $[A,B]$ places $[B,A]$ in
$U_o$: no row at $\{A,B\}$ \outrel both, so the event makes a choice.  In
panel~(g), the two removed route
sets are in $D_o$, each \outrelpast by a retained route set, so the event retires
them without commitment.

Exposability lifts with the event: $o$ is exposable when $\mathsf{output}(o)$
applies no commitment, that is, when $K_o$ and $U_o$ are empty, though the
event may still retire the rows in $D_o$.  The exposure test lifts as well:

\begin{proposition}[Lifted exposure test]
\label{prop:exposability}
An output $o\in R(i)$ is exposable at $(i,R)$ if and only if, for every legal
$j\InputGe i$ and $x\in R(j)$, some $u\in R(j)$ \outrel both:
\begin{equation}
  o\OutputOrd u
  \qquad\text{and}\qquad
  x\OutputOrd u.
  \label{eq:safe-exposure}
\end{equation}
\end{proposition}

\begin{proof}
The event $\mathsf{output}(o)$ applies no commitment exactly when every
ruled-out row $(j,x)$ lies in $D_o$, that is, is \outrelpast by some row
$(j,u)$ \outrelpart $o$.  Rows that already \outrelbase $o$ satisfy the stated
test with $u=x$, so this is exactly the stated test.
\end{proof}

This test marks the commitment boundary: if it fails, emitting $o$ requires a
seal or a choice.

\subsection{Lifted executions and consistency}
\label{sec:relational-executions}

A lifted output event ends at $(i,R[\mathrm{out}\OutputGe o])$, exactly as in
Equation~\ref{eq:output-action}.  Specification states, input events, runs,
commitment-free runs, and consistency are defined as before, and the results
of Section~\ref{sec:determination} used output events only through that
equation.  They therefore lift unchanged: the rows remaining after a run
(Lemma~\ref{lem:run-residual}) and the survivor test
(Proposition~\ref{prop:confluence}).  With them, consistency
reduces to the common-\indesc condition.

\begin{theorem}[Common-\indesc characterization]
\label{thm:common-refinement}
An ordered specification is consistent if and only if it satisfies the
common-\indesc condition.
\end{theorem}

\begin{proof}[Proof sketch]
If the condition holds, a common refinement $u\in S(j)$ of everything emitted survives in every run (Lemma~\ref{lem:run-residual}); conversely, runs that each emit one row's output must share a surviving row at $j$.  Full proof in Appendix~\ref{app:proofs}.
\end{proof}

The same condition governs exposability.

\begin{proposition}[Exposure boundary]
\label{prop:exposure-boundary}
An ordered specification satisfies the common-\indesc condition if and only
if every output at every state reachable without commitment is exposable.
\end{proposition}

\begin{proof}[Proof sketch]
Consistency supplies the refining row the exposure test needs; conversely, applying the exposure test one row at a time builds a common refinement.  Full proof in Appendix~\ref{app:proofs}.
\end{proof}

With one output per input the common-\indesc condition is monotonicity, so
Theorem~\ref{thm:common-refinement} and Proposition~\ref{prop:exposure-boundary}
specialize to Functional CALM (Theorem~\ref{thm:functional-calm}) and
Proposition~\ref{prop:functional-exposure-boundary}.  One result used the
functional dependency itself and does not lift: the surviving row in the
survivor test need not be unique, so neither is the reconciled state, and
Corollary~\ref{cor:state-by-input} fails; Section~\ref{sec:complete-calm}
returns to this.  In place of the functional reduction to monotonicity,
Proposition~\ref{prop:lifted-monotonicity-decomposition} identifies the
common-\indesc condition with Lifted Monotonicity: it is form~(3).  Lifted
Monotonicity is therefore the lifted form of functional monotonicity in a
precise sense: both are the common-\indesc condition, read for one output
per input or for many.

\paragraph{Determination in hindsight.}
Looking back at a run, we can ask what its commitments decided about the
inputs it actually received, as if those inputs had been given up front.
Seals decided nothing about them.

\begin{proposition}[Seals vanish in hindsight]
\label{prop:seals-vanish}
Restricted to the inputs a run receives, the rows removed by its commitments
are exactly the rows removed by its choices.
\end{proposition}

\begin{proof}
Consider a seal applied by $\mathsf{output}(o)$ at $(k,R)$.  The current input
$k$ is not in $K_o$, since its row $(k,o)$ remains.  Inputs received before
$k$ have no rows in $R$, which holds only \indescs of $k$.  An input in $K_o$
has no rows left, so no later input event can receive it.
\end{proof}

In a functional specification every commitment is a seal, so in hindsight a
functional run determined nothing: its commitments were the price of emitting
before its input was complete, as when the registrar closes the polls.  With
several outputs per input, choices remain.  A serialization order must be
chosen even when every transaction is known up front.  What a run determined
about its own input is exactly its choices.

Section~\ref{sec:complete-calm} assembles
Complete CALM from these parts.
