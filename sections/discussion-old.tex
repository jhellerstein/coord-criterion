\section{Discussion}
\label{sec:discussion-old}

\subsection{Design lessons}

The criterion is diagnostic, and four distinctions do most of the work.
First, permitted alternatives belong in the specification as rows, not in an
implementation's nondeterminism, and useful output need not wait for
determination: the election can emit $\bot$ while either candidate may still
win. Second, a removal is classified by its effect on the table. Receiving a
decisive ballot and closing the polls both leave a single result. The first
causes input loss; the second applies an input exclusion to rows that input
still permits. Third, convergent state does not by itself preserve what
replicas reported, so a CRDT state, a read of it, and a query over it can fall
on different sides of the line (\S\ref{sec:crdt-instance}). Finally, a
mechanism coordinates only if it applies an exclusion that another run can
contradict. An uncontended lock excludes nothing, while a local controller can
apply a binding exclusion without communicating. Barriers and end-of-input
markers apply input exclusions, while locks, timestamps, and consensus can
apply output exclusions (Definition~\ref{def:input-output-exclusion}).

\subsection{Scope}
\label{sec:consistency-as-confluence-old}
\label{sec:design-boundary-old}

Our conditions are semantic. Confluence guarantees that a common \outnoun
exists, not that a deployed system reaches it. A participant may lack the
authority to emit it (Appendix~\ref{app:deployment}), and reaching it takes an
algorithm, message delivery, and a termination argument. Participant runs
likewise set aside delivery and strategy details. A state machine induces a
table by pairing environment histories with their observable outputs;
summarizing histories by machine states is a modeling choice that a designer
makes. Protocols, liveness, and cost belong to the operational model in which
a specification is realized.

\subsection{A declarative foundation}

\emph{The Declarative Imperative} stated CALM for monotonic
Datalog~\cite{hellerstein2010declarative}, which tied the coordination
question to a program: its rules, language extensions, and operational
semantics. The specification table is declarative at a lower layer, recording
only which behaviors are permitted and which observations \outrelbase others.
In retrospect, the durable part of the original thesis is that the
coordination question belongs on a declarative description of what is
allowed, not on the code that produces it.
