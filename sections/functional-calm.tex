\section{Functional CALM}
\label{sec:functional-calm}
\jmh{CIDR length: consider keeping statements of the event contract and Lemmas canonical-equivalent and run-residual here and moving their proofs to an appendix.}

The CALM Theorem was proved for queries in a logic programming language,
evaluated by relational transducers, and its applicability outside that
setting was never made precise.  Here we use a simpler model that applies to
any specification expressible as an input/output relation over ordered domains.  A
specification describes allowed input/output
behavior without committing to a language, placement, protocol, or message
schedule.  This section addresses the case that prior work on both CALM and
CRDTs shared: specifications that are functions, in which each
input has a single specified output.  Section~\ref{sec:election-story} walks
through the framework informally on an election.
Section~\ref{sec:functional-specifications} defines specifications, states, and
commitment bases; Section~\ref{sec:functional-events} defines input and output
events; Section~\ref{sec:determination} assembles executions and Consistency;
and Section~\ref{sec:functional-calm-theorem} reduces Consistency to a single
condition on the specification table, proves Functional CALM, and identifies
when an output can be emitted without commitment.

Before the full formalism, we explain the framework by example. We consider a small election,
illustrated in Figure~\ref{fig:election-frames}.  Each row of the specification table pairs
the ballots received so far with the permitted result; orders on the columns
describe how inputs grow and which later outputs \outrelbase earlier ones.  This
section considers tables in which each input has exactly one output;
Section~\ref{sec:ambiguous-specifications} later removes that functional
dependency.

Three voters $v_1,v_2,v_3$ each cast at most one immutable ballot for $x$ or
$y$.  The output is whichever candidate has two ballots, or $\bot$ while there
is no winner.  An input is the ballots received so far, written as a
three-character string with a dot for a ballot not yet received.  For brevity,
the figure shows only inputs \inrelpart $x\cdot\cdot$.

The two orders express different specification decisions.  The \emph{input order}
records accumulated ballots: $xy\cdot$ \inrel $x\cdot\cdot$, while
$xx\cdot$ and $xy\cdot$ are incomparable.  The \emph{output order} records
preservation of visible claims: either winner \outrel $\bot$, while $x$ and
$y$ are incomparable.  In general, the functional table is \emph{monotone}
when
\[
  i\InputOrd j\quad\Longrightarrow\quad f(i)\OutputOrd f(j).
\]
Here, for example, the input sequence $x\cdot\cdot\InputOrd xy\cdot\InputOrd xyx$
monotonically produces the output sequence $\bot\OutputOrd\bot\OutputOrd x$.

\paragraph{Input and determination.}
Each panel captures the specification state: a pair of a \emph{current input}
and a \emph{remainder table} of rows
still possible from that input.  When $v_2$'s ballot for $y$ arrives, the event
$\mathsf{input}(xy\cdot)$ produces panel~(b), retiring rows whose inputs no
longer \inrelbase the ballots received.  The \emph{upper fiber} is the set of
outputs in the remaining rows at the current input and its \indescs; in panel~(b) it is
$\{\bot,x,y\}$.
If $v_2$ instead votes for $x$, as in panel~(c), the upper fiber is $\{x\}$.  The state
is \emph{determined}: input has resolved the ambiguity alone, without commitment.  

In panel~(d), by contrast, a registrar within the system emits $\bot$ and closes the polls at
$xy\cdot$ in the same output event.  Its irrevocable \emph{seal commitment}
removes the still-possible $xyx$ and $xyy$ rows but leaves the current input
unchanged, and so makes $\bot$ the final result.  Emitting $\bot$ by itself
would need no commitment, since every output still possible \outrel it;
closing the polls is a further decision by the system, not something the
specification requires.
A \emph{system} is what implements the specification
(Section~\ref{sec:histories} makes this precise); commitments belong to a
system's declared \emph{commitment basis} $\mathcal B$,
not to the specification itself; a system whose polls cannot close does not
have this commitment in its basis.

\paragraph{Output and consistency.}
In a functional table, an output $o$ is \emph{exposable} when every output
still possible at the current input or an \indesc still in the table \outrel it.  Hence $\bot$ is exposable
in panels~(a) and~(b), and $x$ in panel~(c).  The atomic $\mathsf{output}(o)$
event applies any seal commitments needed so that $o$ becomes exposable,
then emits $o$, in one transition.  Emitting $o$ is a promise:
from then on, only rows whose outputs \outrelbase $o$ remain.  The emission stays
explicit in the history because the uncontrolled environment may use it when
choosing later input.

Figure~\ref{fig:nonmonotone-frame} considers a variant of our example that
changes only the output order: all outputs are incomparable, including $\bot$
for no winner (the \emph{equality order}, under which each element is related only
to itself).  At $x\cdot\cdot$, $\bot$ is then incompatible with future
winners.  Emitting it requires sealing those winner-producing \indescs; the
figure shows the stronger, optional action of closing the polls and sealing all
\indescs, including $xy\cdot$, which also outputs $\bot$.  This isolates the
Functional CALM boundary: under the original monotone order, outputs remain
valid as input grows; under the equality order, some outputs require commitment
before they can be emitted.

The obstruction is a property of the table alone.  Rows $(x\cdot\cdot,\bot)$ and
$(xx\cdot,x)$ have the common \indesc $xxx$, but under the equality
order no output at $xxx$ \outrel both outputs $\bot$ and $x$.  A run that emits $\bot$ at $x\cdot\cdot$ and one
that receives $xx\cdot$ cannot be reconciled at $xxx$.

Input and output events form a transition system between system states.  A
specification is \emph{consistent} when its runs are confluent: any runs whose inputs have a common
\indesc can always be continued to one common state there.
Section~\ref{sec:functional-calm-theorem} shows that the test above is exactly
what consistency requires: outputs at inputs with a common \indesc $j$ must
have a common \outnoun at $j$.  For functional tables this test is monotonicity,
which is Functional CALM.

The rest of this section formalizes these notions; Figure~\ref{fig:formalism-summary}
serves as a reference.

\subsection{Specifications, states, and commitments}
\label{sec:functional-specifications}

We begin by defining the core structures of our framework: specifications and commitment bases.
\begin{definition}[Functional ordered specification]
\label{def:functional-specification}
A \emph{functional ordered specification} is a tuple
\[
  \Spec=(I,\InputOrd,O,\OutputOrd,S),
\]
where $(I,\InputOrd)$ and $(O,\OutputOrd)$ are partially ordered input and
output types, and $S\subseteq I\times O$ is a typed relation with schema
$(\mathrm{in},\mathrm{out})$ in which every
input appears in at least one row ($S$ is \emph{total} on $I$) and at most one
(the functional dependency):
\[
  (i,o)\in S\ \land\ (i,o')\in S
  \quad\Longrightarrow\quad o=o'.
\]
\end{definition}

The unique output paired with $i$ induces the function
\[f:(I,\InputOrd)\to(O,\OutputOrd)\]
with $S=\{(i,f(i)):i\in I\}.$
We call
$\InputOrd$ the \emph{input order}: $i\InputOrd j$ means that $j$
contains at least the input information in $i$, and we say that $j$
\emph{\inrel} $i$, or is an \emph{\indesc} of $i$; every input is an \indesc of itself.  We call $\OutputOrd$ the
\emph{output order}: $o\OutputOrd u$ means that $u$ preserves every
externally visible claim in $o$ and may add more, and we say that $u$
\emph{\outrel} $o$.  We use these two verbs only in these senses: inputs
\ingrow, and outputs are \outrelpast.  We write $\InputGe$ and
$\OutputGe$ for the converse orders.  A \emph{common \indesc} of inputs
$i_1,\ldots,i_k$ is an input $j$ that \inrel every $i_r$, and a
\emph{common \outnoun} of outputs is an output that \outrel each of them.
A row $(k,u)$ is \emph{\outrelpast} by another row $(k,w)$ at the same input
when $w$ \outrel $u$.
Section~\ref{sec:ambiguous-specifications}
drops the functional dependency; we say \emph{ordered specification} for
either kind.

The two orders are independent: the input order compares inputs; the output
order compares outputs.  Either may be the equality order of
Section~\ref{sec:election-story}.

\begin{definition}[Functional monotonicity]
\label{def:functional-monotonicity}
A functional ordered specification $\Spec$, with induced function $f$, is
\emph{monotone} if
\begin{equation}
  i\InputOrd j
  \quad\Longrightarrow\quad
  f(i)\OutputOrd f(j).
  \label{eq:functional-monotonicity}
\end{equation}
\end{definition}

Thus an output emitted from partial input remains valid as more input arrives.

\paragraph{Relational notation.}
To describe how execution narrows $S$, we use a compact relational notation.
For any relation
$R\subseteq I\times O$, we select rows by writing a predicate on its
columns $\mathrm{in}$ and $\mathrm{out}$ in square brackets: $R[\mathrm{in}\InputGe j]$ is the table of rows
whose input \inrel $j$, $R[\mathrm{out}\OutputGe o]$ is the table of rows
whose output \outrel $o$, and $R[\mathrm{in}=k]$ and $R[\mathrm{in}\in K]$ are
the tables of rows at $k$ and at inputs in $K$.  Commas separate conjuncts:
$R[\mathrm{in}\InputGe j,\ \mathrm{out}\OutputGe o]$ is the table of rows
satisfying both predicates.  A selection is again a table.
To project onto a single column, we write $\mathrm{in}(R)$ and
$\mathrm{out}(R)$ for the sets of inputs and outputs that appear in $R$, and
$R(k)=\mathrm{out}(R[\mathrm{in}=k])$ for the \emph{fiber} of $R$ at $k$.

A specification describes every permitted input/output pair.  During execution,
input arrives and choices become binding, so only some of those pairs remain
possible.  The changing state of the specification is defined as follows.

\begin{definition}[Specification state]
\label{def:residual-state}
Given a specification $\Spec=(I,\InputOrd,O,\OutputOrd,S)$, a \emph{specification state} is a
pair $\sigma=(i,R)$, where $i\in I$ is the \emph{current input} and
$R\subseteq S$ is the \emph{remainder table}, such that:
\begin{enumerate}
  \item $R$ contains a row at $i$; and
  \item every row $(k,o)\in R$ satisfies $i\InputOrd k$.
\end{enumerate}
An input $k$ is \emph{legal} at $\sigma$ when $R$ contains a row at $k$.
\end{definition}

Rows are never added during execution.  For each input $i$, the \emph{canonical
state at $i$} retains all rows at $i$ and its \indescs:
\begin{equation}
  \sigma_S(i)=\bigl(i,\ S[\mathrm{in}\InputGe i]\bigr).
  \label{eq:canonical-state}
\end{equation}

The specification and its states say which behaviors are possible, but not
which possibilities the system is authorized to rule out.  That authority is a
separate part of the model, as follows.

\begin{definition}[Commitment, commitment basis, seal]
\label{def:commitment-basis}
A \emph{commitment} is a partial function on specification states that leaves
the current input unchanged and removes a nonempty set of rows, each with no remaining
row at the same input that \outrel it: whenever $c(i,R)=(i,R')$, we have $R'\subsetneq R$ and
\begin{equation}
  (k,u)\in R\setminus R',\ (k,w)\in R'
  \quad\Longrightarrow\quad
  u\not\OutputOrd w.
  \label{eq:commitment-excludes}
\end{equation}
A \emph{commitment basis}
$\mathcal B$ is a set of commitments available to a system.  A commitment
\emph{seals} a legal input $k$ when it empties the fiber at $k$.
\end{definition}

In a functional specification each input has one row, so no other row shares
a removed row's input and Equation~\ref{eq:commitment-excludes} holds
vacuously; every commitment seals the inputs whose rows it removes; we call it a
\emph{seal commitment}.  A commitment makes an allowed future unreachable.
Section~\ref{sec:safe-exposure} shows what the condition adds when an input has
several outputs.

Note that commitments are \emph{partial} functions:  a system may be designed to
authorize a commitment only at states satisfying an application-specific
precondition.  For example, in Figure~\ref{fig:election-frames}(d), we defined the
poll-closing commitment at every state; a different system might authorize it
only after some candidate has a majority.

\subsection{Input and output events}
\label{sec:functional-events}

States and commitment bases tell us what remains possible and what a system may
rule out.  We now define the two events that change state: input events
incorporate new information, while output events record promises to the outside
world.

\paragraph{Input events.}
For a state $(i,R)$ and legal input $j$ with $i\InputOrd j$, the input event is
\begin{equation}
  (i,R)\xrightarrow{\mathsf{input}(j)}
  \bigl(j,\ R[\mathrm{in}\InputGe j]\bigr).
  \label{eq:input-event}
\end{equation}
It makes $j$ current and \emph{retires} every row failing the predicate: i.e.,
those whose input does not \inrelbase
$j$. We call this \emph{input retirement}.

An input event records a new cumulative input $j$, not how $j$ was
assembled.\footnote{The framework does not require cumulative inputs to come
from a least common \indesc or a lattice, only that they grow according to
$\InputOrd$.  For example, transaction schedules ordered by subsequence form a
partial order but not a lattice: two independent events $a$ and $b$ have two
incomparable minimal common \indescs, $ab$ and $ba$.}  Because inputs are
cumulative, applying $\mathsf{input}(j)$ and then $\mathsf{input}(k)$ has the
same effect as applying $\mathsf{input}(k)$ directly; $\mathsf{input}(i)$ at
$(i,R)$ has no effect.

\paragraph{Output events.}
A system controls what it tells the outside world.  We study what it can safely
promise without assuming that clients tolerate retractions.  An emitted output
must therefore be \outrelpast by later outputs.

At state $(i,R)$, the current input has a unique row $(i,o)$, so $o$ is the only
output the system may emit.  Before doing so, it must seal every legal
future input whose output does not \outrelbase $o$.

\begin{definition}[Output event]
\label{def:output-event}
Let $(i,R)$ be a state and $o\in R(i)$.  An \emph{output event}
$\mathsf{output}(o)$ under a basis $\mathcal B$ applies a finite, possibly
empty sequence of commitments from $\mathcal B$ and then emits $o$, all
atomically.  If the commitments leave remainder table $R'$, the event is
\emph{legal} at $(i,R)$ when every remaining row's output \outrel $o$:
\begin{equation}
  (k,u)\in R' \Longrightarrow o\OutputOrd u,
  \quad\text{or equivalently}\quad R'\subseteq R[\mathrm{out}\OutputGe o].
  \label{eq:supported-output-action}
\end{equation}
\end{definition}

Which commitments an output event can apply depends on the system's basis.
Our proofs instead use a canonical basis derived from $S$: for each permitted
output, it removes exactly the rows incompatible with that output's promise.

\begin{definition}[Canonical seal commitment, canonical basis]
\label{def:canonical-commitment-basis}
For a state $(i,R)$ and its current row $(i,o)$, retaining the promise made by
$o$ permits exactly the rows whose outputs \outrelbase $o$:
\begin{equation}
  R[\mathrm{out}\OutputGe o]=\{(k,u)\in R:o\OutputOrd u\}.
  \label{eq:residual-refining-fibers}
\end{equation}
For each $o\in O$, the \emph{canonical seal commitment} $s_o$ is the partial
function
\begin{equation}
  s_o(i,R)=(i,R[\mathrm{out}\OutputGe o]),
  \label{eq:canonical-seal-commitment}
\end{equation}
defined at every specification state $(i,R)$ where $(i,o)\in R$ and
$R[\mathrm{out}\OutputGe o]\neq R$.  In a functional specification it seals
exactly the legal inputs whose
outputs do not \outrelbase $o$.  The \emph{canonical commitment basis} is exactly
\begin{equation}
  \mathcal B_S
    =\{s_o:o\in O,\ \operatorname{dom}(s_o)\neq\varnothing\}.
  \label{eq:canonical-commitment-basis}
\end{equation}
\end{definition}

In an output event, commitments leave the current input unchanged and yield
states, so the remaining table $R'$ still contains the current row $(i,o)$.  The \emph{canonical event} retains exactly
the compatible rows:
\begin{equation}
  (i,R)\xrightarrow{\mathsf{output}(o)}(i,R[\mathrm{out}\OutputGe o]).
  \label{eq:output-action}
\end{equation}
It applies $s_o$ when $R[\mathrm{out}\OutputGe o]\neq R$, and no commitment otherwise.

\begin{definition}[Exposable output]
\label{def:exposable}
An output $o\in R(i)$ is \emph{exposable} at $(i,R)$ when some legal output
event for $o$ applies no commitment.
\end{definition}

Systems differ in which commitments they hold, so one output can be emitted by
many different events.  To reason about all of them at once, we isolate what
they share.  No system-specific basis retains more rows than the canonical
event, and the results that follow depend on output events only through four
facts, which we collect as the \emph{event contract}.  We prove it here for
functional specifications; Section~\ref{sec:safe-exposure} proves it again with
several outputs per input.

\begin{proposition}[Event contract]
\label{prop:canonical-output-preservation}
Let $(i,R)$ be a state and $o\in R(i)$.
\begin{enumerate}
  \item \emph{Containment.}  Under any commitment basis, a legal output event
        for $o$ takes $(i,R)$ to some $(i,R')$ with
        $R'\subseteq R[\mathrm{out}\OutputGe o]$.
  \item \emph{Canonical support.}  The canonical event for $o$ is legal at
        $(i,R)$ and takes it to $(i,R[\mathrm{out}\OutputGe o])$.  It therefore
        retains every row that any legal event for $o$ retains.
  \item \emph{Commitment-free events are canonical.}  A legal output event for
        $o$ that applies no commitment takes $(i,R)$ to
        $(i,R[\mathrm{out}\OutputGe o])$.
  \item \emph{Exposure test.}  The output $o$ is exposable at $(i,R)$ if and
        only if, for every legal $j\InputGe i$ and every $x\in R(j)$, some
        $u\in R(j)$ \outrel both $o$ and $x$.
\end{enumerate}
\end{proposition}

\begin{proof}
Containment is Equation~\ref{eq:supported-output-action}, and canonical
support is Equation~\ref{eq:output-action}.  An output event that applies no
commitment leaves $R$ unchanged, so it is legal exactly when
$R\subseteq R[\mathrm{out}\OutputGe o]$, in which case
$R=R[\mathrm{out}\OutputGe o]$; this gives clause~3.  That condition says
$o\OutputOrd f(j)$ at every legal $j\InputGe i$; since $R(j)=\{f(j)\}$, taking
$u=x=f(j)$ shows that it is the condition of clause~4.
\end{proof}

In a functional specification, then, $o$ is exposable exactly when
$R[\mathrm{out}\OutputGe o]=R$, or equivalently $o\OutputOrd f(j)$ at every
legal $j\InputGe i$.

\paragraph{Determination.}
Both kinds of event can narrow what remains possible.  For a state $(i,R)$, the
\emph{upper fiber} $\mathrm{out}(R[\mathrm{in}\InputGe i])$ collects the
outputs at $i$ and its legal \indescs.  The state is
\emph{determined} when its upper fiber has one element, regardless of how it
was reached.
\emph{Determination} is movement toward or arrival at a determined state.  An
input event may resolve ambiguity by retiring rows that no longer \inrelbase the
input received; a commitment may instead exclude an alternative that otherwise
remains possible, as in panels (c) and (d) of
Figure~\ref{fig:election-frames}.

\subsection{Executions and consistency}
\label{sec:determination}

We now assemble events into runs and ask the central consistency question:
when different runs follow different paths through the specification, can
their resulting states still be reconciled?  Consistency quantifies over all
runs of all systems.  We reduce it to a check
on the specification table in three steps.  First, any system's run can be
replaced by a canonical run that keeps at least as many rows
(Lemma~\ref{lem:canonical-equivalent}).  Second, a canonical run's remaining
rows depend only on its current input and the outputs it has emitted
(Lemma~\ref{lem:run-residual}).  Third, runs are therefore confluent exactly
when one row at their common input survives in all of them
(Proposition~\ref{prop:confluence}), which yields a condition on the table
alone (Theorem~\ref{thm:common-refinement}, Section~\ref{sec:functional-calm-theorem}).
None of these steps uses the functional dependency; they use output events only
through the event contract of Section~\ref{sec:functional-events}.
Section~\ref{sec:ambiguous-specifications} re-verifies that contract for
several outputs per input, and every step then carries over.

\begin{definition}[Transition system, run, canonical run]
\label{def:io-transition-system}
\label{def:transition-system}
The \emph{transition system} consists of specification states and the input and
output events above.  Fix a commitment basis $\mathcal B$.  A \emph{run under
$\mathcal B$} is any finite transition sequence from the canonical state
$\sigma_S(i)$ at some input $i$; its output events may use only commitments
from $\mathcal B$.  We say simply \emph{run} when the basis is clear.  A
\emph{canonical run} is a run under $\mathcal B_S$ in which every output event
takes the canonical transition of Equation~\ref{eq:output-action}.
\label{def:run}
\end{definition}

A run is \emph{commitment-free} when none of its output events applies a
commitment.  By clause~3 of the event contract, a commitment-free run under any
basis is a canonical run.  A state is \emph{reachable without commitment} when
some commitment-free run reaches it.

Our results quantify over canonical runs rather than over the runs of any
particular system.  To see that this excludes no system's behavior, call two
runs \emph{equivalent} when they start at the same canonical state and have the
same sequence of event labels: they accept the same inputs and emit the same
outputs, in the same order.  Equivalent runs may differ in the commitments
their output events apply, and hence in their remainder tables.  We lift
Proposition~\ref{prop:canonical-output-preservation} from single output events
to runs:

\begin{lemma}[Canonical equivalents]
\label{lem:canonical-equivalent}
Every run under any commitment basis is equivalent to a canonical run.  After
each event, the canonical run's remainder table contains the original run's.
\end{lemma}

\begin{proof}
By induction on the events.  Both runs start at the same canonical state, so
their remainder tables are initially equal.  Suppose that before some event the
original run's table $R$ and the canonical run's table $\widehat R$ satisfy
$R\subseteq\widehat R$; we show that the inclusion holds afterward.  An input
event $\mathsf{input}(j)$ that is legal at $R$ is also legal at $\widehat R$.
It retires every row whose input does not \inrelbase $j$, keeping
$R[\mathrm{in}\InputGe j]$ in the original run and
$\widehat R[\mathrm{in}\InputGe j]$ in the canonical run.  Since
$R\subseteq\widehat R$, the first remains contained in the second.  For an
output event for $o\in R(i)$ taking $R$ to $R'$, containment
(Proposition~\ref{prop:canonical-output-preservation}) gives
$R'\subseteq R[\mathrm{out}\OutputGe o]$.  Since $o\in R(i)\subseteq\widehat R(i)$,
canonical support applies at $\widehat R$: the canonical event takes
$\widehat R$ to $\widehat R[\mathrm{out}\OutputGe o]$, which contains
$R[\mathrm{out}\OutputGe o]$.
\end{proof}

The converse does not hold: a canonical run need not be equivalent to any run
under a particular system's basis.  That basis may lack the commitment an
output event requires, and so disable the output altogether.  Restricting
attention to one system's runs could therefore hide non-monotonicity.  This is
why Consistency, below, uses the canonical basis rather than a system's own.

A canonical run's state has a simple description.  Input events keep only rows
whose input \inrel the current one, and output events keep only rows whose
outputs \outrelbase what has been emitted.  Both steps are selections, and selections commute.  So
the remainder table depends only on the current input and the outputs emitted
so far, not on the order of events or the inputs passed through along the way.

\begin{lemma}[Rows remaining after a canonical run]
\label{lem:run-residual}
If a canonical run ends at current input $i$ after emitting
$o_1,\ldots,o_m$, its remainder table is
\begin{equation}
  S[\mathrm{in}\InputGe i,\ \mathrm{out}\OutputGe o_1,\ \ldots,\
    \mathrm{out}\OutputGe o_m],
  \label{eq:run-residual}
\end{equation}
the rows whose input \inrel $i$ and whose output \outrel every emitted
output.
\end{lemma}

\begin{proof}
The run starts at a canonical state $\sigma_S(i_0)$, whose remainder table is
$S[\mathrm{in}\InputGe i_0]$.  Each input event adds a conjunct
$\mathrm{in}\InputGe j$ and, by canonical support
(Proposition~\ref{prop:canonical-output-preservation}), each canonical output
event a conjunct $\mathrm{out}\OutputGe o$; since inputs only grow, the input
conjuncts reduce to the last one: $\mathrm{in}\InputGe i$.
\end{proof}

For example, in Figure~\ref{fig:nonmonotone-frame}'s equality-order variant, a
canonical run that emits $\bot$ at $x\cdot\cdot$ keeps
$S[\mathrm{in}\InputGe x\cdot\cdot,\ \mathrm{out}\OutputGe\bot]$: the rows
$(x\cdot\cdot,\bot)$ and $(xy\cdot,\bot)$.  The registrar in the figure also
removes $(xy\cdot,\bot)$, a stronger commitment than the specification
requires.

To compare runs that end at different inputs, we consider a common \indesc
of those inputs.

\begin{definition}[Consistency]
\label{def:consistency}
An ordered specification is \emph{consistent} when every finite family of
canonical runs is confluent: if the runs end at states
$(i_1,R_1),\ldots,(i_k,R_k)$ and $j$ is a common \indesc of their current
inputs, each run can be continued by further canonical events to one common
state with current input $j$.  The runs are then \emph{confluent at} $j$.
\end{definition}

Confluence has a simple test: some row at the common \indesc must survive
in every run.

\begin{proposition}[Survivor test]
\label{prop:confluence}
Canonical runs ending at states $(i_1,R_1),\ldots,(i_k,R_k)$ are confluent
at $j$ if and only if some row at $j$ survives in every final state:
\begin{equation}
  (j,u)\in R_r\quad\text{for every }r,\ \text{for some }u\in O.
  \label{eq:reconciliation}
\end{equation}
For any such $u$, $\mathsf{input}(j)$ followed by $\mathsf{output}(u)$ takes
every endpoint to the state
$\bigl(j,\ S[\mathrm{in}\InputGe j,\ \mathrm{out}\OutputGe u]\bigr)$.
\end{proposition}

\begin{proof}
A common state with current input $j$ has a row at $j$, and since rows are
never added, that row belongs to every $R_r$.  Conversely, let $(j,u)$ belong
to every $R_r$.  Then $\mathsf{input}(j)$ is defined at every $(i_r,R_r)$.  By
Lemma~\ref{lem:run-residual}, $(j,u)\in R_r$ says that $u$ \outrel every output
emitted on run $r$.  After $\mathsf{input}(j)$ and $\mathsf{output}(u)$, the
same lemma leaves exactly
$S[\mathrm{in}\InputGe j,\ \mathrm{out}\OutputGe u]$, independent of the
starting run.
\end{proof}

In a functional specification the only row at $j$ is $(j,f(j))$, so the test
asks whether that row survives in every run, and $u=f(j)$; in the
equality-order election of Section~\ref{sec:election-story}, the row
$(xxx,x)$ does not survive the run that emits $\bot$ at $x\cdot\cdot$.

Consistency guarantees that runs never diverge irreparably.  Whatever input
and output events a finite collection of runs has taken, any input \inrelpart all
of theirs leaves a single state that every run can reach: one that keeps every
promise any of them has made and accepts all of that input.
Proposition~\ref{prop:confluence} identifies that state, and
Section~\ref{sec:functional-calm-theorem} shows that for a consistent
functional specification it depends only on the input.

Consistency is a property of the specification.  It describes no protocol and
promises no delivery or termination; Section~\ref{sec:discussion} returns to
this.

\subsection{The Functional CALM theorem}
\label{sec:functional-calm-theorem}

Consistency is a property of families of canonical runs, while monotonicity
is a local condition on pairs of inputs.  We first characterize Consistency by
a condition on the specification table alone, then specialize it to
functional specifications.

\begin{definition}[Common-\indesc condition]
\label{def:common-refinement-condition}
An ordered specification satisfies the \emph{common-\indesc condition} when,
for every finite set of rows $(i_1,o_1),\ldots,(i_k,o_k)$ of $S$ and every
common \indesc $j$ of $i_1,\ldots,i_k$, some $u\in S(j)$ \outrel every
$o_r$.
\end{definition}

The inputs $i_r$ need not be comparable, because different runs meet only at a
common \indesc.  For the empty set of rows the condition asks only that
$S(j)$ be nonempty, which totality guarantees.

\begin{theorem}[Common-\indesc characterization]
\label{thm:common-refinement}
An ordered specification is consistent if and only if it satisfies the
common-\indesc condition.
\end{theorem}

\begin{proof}
Suppose the condition holds, and let canonical runs end at $(i_r,R_r)$ with
common \indesc $j$.  Each output $o$ emitted on a run was emitted at some
input $i_o\InputOrd j$, and since $o\in R(i_o)\subseteq S(i_o)$, it forms a row
$(i_o,o)$ of $S$.  The condition supplies $u\in S(j)$ \outrelpart all of these
outputs.  Since $j$ \inrel every current input $i_r$,
Lemma~\ref{lem:run-residual} puts $(j,u)$ in every $R_r$, and
Proposition~\ref{prop:confluence} gives confluence at $j$.  Conversely, let
rows $(i_r,o_r)$ have common \indesc $j$.  For each $r$, the canonical run
that starts at $\sigma_S(i_r)$ and emits $o_r$ ends with remainder table
$S[\mathrm{in}\InputGe i_r,\ \mathrm{out}\OutputGe o_r]$
(Lemma~\ref{lem:run-residual}).  Consistency and
Proposition~\ref{prop:confluence} supply a row $(j,u)$ surviving in every one
of these runs, so $u\in S(j)$ \outrel every $o_r$.
\end{proof}

In the equality-order election, the rows $(x\cdot\cdot,\bot)$ and $(xx\cdot,x)$
have common \indesc $xxx$, but $S(xxx)=\{x\}$ and $x$ does not \outrelbase
$\bot$.  The condition fails, and so does Consistency: these are the two runs of
Section~\ref{sec:election-story} that can never meet.

\begin{theorem}[Functional CALM]
\label{thm:functional-calm}
A functional ordered specification is consistent if and only if it is
monotone.
\end{theorem}

\begin{proof}
By Theorem~\ref{thm:common-refinement}, it suffices to show that, for a
functional specification, the common-\indesc condition is equivalent to
monotonicity.  The rows of $S$ are $(i_r,f(i_r))$ and $S(j)=\{f(j)\}$, so the
condition says that $f(i_r)\OutputOrd f(j)$ whenever $i_r\InputOrd j$.  With
one row this is monotonicity, and monotonicity gives it for every row.
\end{proof}

In the functional case, Consistency has a strong consequence: outputs leave no
trace on the state.

\begin{corollary}[State is determined by input]
\label{cor:state-by-input}
In a consistent functional specification, every canonical run ending at current
input $i$ is in the canonical state $\sigma_S(i)$, whatever outputs it emitted
along the way.
\end{corollary}

\begin{proof}
By Functional CALM (Theorem~\ref{thm:functional-calm}), the specification is
monotone.  By Lemma~\ref{lem:run-residual}, the run's remainder table is
$S[\mathrm{in}\InputGe i,\ \mathrm{out}\OutputGe o_1,\ \ldots,\
\mathrm{out}\OutputGe o_m]$, where each $o_\ell=f(i_\ell)$ for some
$i_\ell\InputOrd i$.  Every row whose input \inrel $i$ has the form $(k,f(k))$ with
$i_\ell\InputOrd k$, so monotonicity gives $o_\ell\OutputOrd f(k)$, and the
output conditions remove nothing.
\end{proof}

Confluence at a common \indesc $j$ therefore needs only $\mathsf{input}(j)$:
every run reaches $\sigma_S(j)$, the state of a run that starts with all of the
input.  Knowing the input is enough to know the state, and with it the one
output $f(j)$.

Exposability, too, is governed by the common-\indesc condition:

\begin{proposition}[Exposure boundary]
\label{prop:functional-exposure-boundary}
An ordered specification satisfies the common-\indesc condition if and only
if every output at every state reachable without commitment is exposable.
\end{proposition}

\begin{proof}
Suppose the condition holds; by Theorem~\ref{thm:common-refinement}, the
specification is consistent.  Let $(i,R)$ be reached by a commitment-free run,
which is canonical, and let $o\in R(i)$, $j\InputGe i$ legal, and
$x\in R(j)$.  Extend the run in two ways: by $\mathsf{output}(o)$, and by
$\mathsf{input}(j)$ followed by $\mathsf{output}(x)$.
Proposition~\ref{prop:confluence} supplies a row $(j,u)$ surviving in both, so
$u\in R(j)$ \outrel $o$ and $x$, and the exposure test
(Proposition~\ref{prop:canonical-output-preservation}) makes $o$ exposable.
Conversely, suppose every such output is exposable, and let rows
$(i_1,o_1),\ldots,(i_k,o_k)$ have common \indesc $j$.  By totality pick
$u_0\in S(j)$.  For $r=1,\ldots,k$ in turn, the exposure test for $o_r$ at
$\sigma_S(i_r)$, applied with $x=u_{r-1}$, gives $u_r\in S(j)$ \outrelpart both
$o_r$ and $u_{r-1}$.  Then $u_k$ \outrel every $o_r$.
\end{proof}

For a functional specification, Functional CALM turns the condition into
monotonicity.  Since every commitment of a functional specification is a seal,
the two results together say that a functional specification is consistent
exactly when, at every state reachable without commitment, no output requires
sealing input.  A monotone functional specification can emit every current
output without a commitment; if monotonicity fails at $i\InputOrd k$ with
$f(i)\not\OutputOrd f(k)$, the canonical output event for $f(i)$ seals $k$.

This is the familiar CALM dichotomy stated at the level of the specification
rather than inside a particular programming language.  The C in CALM has been read
both as consistency and as confluence; Definition~\ref{def:consistency} is
both.  Classical CALM fits the pattern with inputs $J$ ordered by fact
inclusion and outputs $Q(J)$ ordered by answer inclusion.  Functional
monotonicity becomes
        \begin{equation}
  J\subseteq J'
  \quad\Longrightarrow\quad
  Q(J)\subseteq Q(J'),
  \label{eq:query-monotonicity}
        \end{equation}
the standard definition of a monotone query~\cite{abiteboul1995foundations},
which positive Datalog satisfies and negation may not.  Functional CALM
generalizes the statement from fact sets under inclusion to arbitrary input and
output orders, regardless of the formalism used to express the
specification.  The usual CRDT state specification has the same functional shape,
with received payloads ordered by inclusion and states by the semilattice
order~\cite{shapiro2011crdt}; Sections~\ref{sec:query-instance}
and~\ref{sec:crdt-instance} take up both instances.

Before dropping the functional dependency, we give this consistency condition
a distributed interpretation.  Section~\ref{sec:distributed-execution}
realizes runs as participant runs; the construction will apply unchanged when
Section~\ref{sec:ambiguous-specifications} allows several outputs per input.
