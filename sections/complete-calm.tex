\section{Complete CALM}
\label{sec:complete-calm}

We now extend CALM theory to nondeterministic specs, whose fibers may contain
several outputs.

\subsection{Nondeterministic specs and Lifted Monotonicity}
\label{sec:relational-specifications}

\begin{definition}[\Spectype]
\label{def:relational-specification}
An \emph{\spectype} is
        \begin{equation}
  \Spec=(I,\InputOrd,O,\OutputOrd,P),
  \qquad P\subseteq I\times O,
  \label{eq:relational-specification}
        \end{equation}
  where $(I,\InputOrd)$ and $(O,\OutputOrd)$ are partially ordered sets and
  $P\subseteq I\times O$ is its \emph{possibility relation}.  We depict $P$ as
a table and call its members rows; it need not be finite.  The relation $P$
  is total on $I$: every input appears in at least one row.  A row $(i,o)\in P$
  is a possible input/output pair: output $o$ is permitted at input $i$.  The fiber
        \begin{equation}
  \fiber{i}=\{o\in O:(i,o)\in P\}
  \label{eq:fiber}
        \end{equation}
of Section~\ref{sec:functional-specifications} may now contain several
  outputs.  A functional \spectype is the special case $\fiber{i}=\{f(i)\}$.
\end{definition}

\begin{definition}[Nondeterministic \spectype]
\label{def:nondeterministic}
An \spectype is \emph{nondeterministic} when some fiber
contains more than one output.  Specification nondeterminism describes
permitted results, not a strategy's method of choosing among them, and does not
by itself imply a \commitment.
\end{definition}

Specification states and input events
(Sections~\ref{sec:functional-specifications} and~\ref{sec:functional-events})
apply unchanged to relational tables.

Figure~\ref{fig:ambiguity-frames} contrasts two specs with several outputs in
one fiber: serial schedules for two transactions and route sets observed by a
traceroute-like tool.  For the discussion here, transaction outputs are simply
serial schedules, to which executions correspond via equivalence;
Section~\ref{sec:hat-instance} and Appendix~\ref{app:cc-bases} study more
thorough transactional specs.

The transaction schedules $[A,B]$ and $[B,A]$ are incompatible, so emitting
either requires a \commitment that removes the other.  In the traceroute spec,
every removed route set is \outrelpast by a remaining one that also \outrelbase
the emitted observation, making its removal \emph{output subsumption} rather
than \commitment.  Lifted Monotonicity combines directedness, which requires
common \outnouns within each fiber, with Relational Monotonicity, which
accounts for input growth.

\label{sec:lifted-monotonicity}
\begin{definition}[Relational Monotonicity]
\label{def:relational-monotonicity}
An \spectype satisfies \emph{Relational Monotonicity}
when every output keeps some \outnoun as input \ingrows:
        \begin{equation}
  i\InputOrd j,\ o\in\fiber{i}
  \quad\Longrightarrow\quad
  \exists u\in\fiber{j}:\ o\OutputOrd u.
  \label{eq:relational-monotonicity}
        \end{equation}
\end{definition}

For singleton fibers this is functional monotonicity,
Equation~\ref{eq:functional-monotonicity}.  It treats each output separately,
so it does not require several outputs in one fiber to have a common \outnoun.
For a set $F\subseteq O$ of outputs, outputs $o_1,\ldots,o_k$ are
\emph{compatible in $F$} if some $u\in F$ \outrel all of them, and
\emph{incompatible in $F$} otherwise.

\begin{definition}[Directed fiber]
\label{def:fiber-directedness}
A fiber $F\subseteq O$ is \emph{directed} when every nonempty finite
$X\subseteq F$ is compatible in $F$.
\end{definition}

\begin{definition}[Directed fibers]
\label{def:directed-outputs}
An \spectype has \emph{directed fibers} when every
fiber $\fiber{i}$ is directed.
\end{definition}

A singleton fiber is trivially directed.  As with common \indescs,
(Section~\ref{sec:functional-specifications}), a common \outnoun need not be
least: directedness requires some upper bound within the fiber for each finite
set, not a least one or a fixed merge operator, so it is weaker than a
join-semilattice.  For example, the fiber
$\{\{a\},\{b\},\{a,b,c\},\{a,b,d\},\{a,b,c,d\}\}$ under inclusion is directed,
since $\{a,b,c,d\}$ \outrel every member, yet $\{a\}$ and $\{b\}$ have two
incomparable minimal common \outnouns.  Compatibility likewise does not require
comparability: two incomparable outputs may have a third output in the fiber
that \outrel both, as $\{a,b,c\}$ and $\{a,b,d\}$ do in the fiber above.  Thus
the traceroute fiber is directed: the union of finitely many route sets in it is again in the fiber and extends each. The two transaction orders in
Figure~\ref{fig:ambiguity-frames}(f), by contrast, are incompatible.

\paragraph{Lifted Monotonicity.}
To state both requirements at once, lift $\OutputOrd$ to sets.  For nonempty
$A,B\subseteq O$, define
        \begin{equation}
  A\LiftedOrd B
  \;\Longleftrightarrow\;
  \text{every nonempty finite }X\subseteq A\text{ is compatible in }B,
  \label{eq:joint-output-order}
        \end{equation}
the \emph{joint refinement lift} of $\OutputOrd$.  We apply it with $A=\fiber{i}$ and
$B=\fiber{j}$ for $i\InputOrd j$.  When $X$ is a single output $o$, it asks
that $o$ have a \outnoun in $\fiber{j}$, which is Relational Monotonicity.
When $X$ holds several outputs, it asks that they have a common \outnoun in
$\fiber{j}$; with $j=i$, this is directedness.

\begin{definition}[Lifted Monotonicity]
\label{def:lifted-monotonicity}
An \spectype satisfies \emph{Lifted Monotonicity}, and
is called \emph{monotone}, when the mapping $i\mapsto\fiber{i}$ is monotone
under the joint refinement lift:
        \begin{equation}
  i\InputOrd j
  \quad\Longrightarrow\quad
  \fiber{i}\LiftedOrd\fiber{j}.
  \label{eq:lifted-monotonicity}
        \end{equation}
\end{definition}

With singleton fibers it is functional monotonicity
(Definition~\ref{def:functional-monotonicity}).  As the reading above shows,
it implies Relational Monotonicity and the spec has directed fibers;
conversely, for $i\InputOrd j$ and finite nonempty $X\subseteq\fiber{i}$,
Relational Monotonicity gives each $x\in X$ a \outnoun in $\fiber{j}$, and
because the spec has directed fibers, those outputs have a common
\outnoun in $\fiber{j}$.  So Lifted Monotonicity
holds exactly when both do.  In powerdomain terms, Relational Monotonicity
is monotonicity of $i\mapsto\fiber{i}$ under the Hoare
preorder~\cite{abramsky1994domain}, which asks only that each output in $A$
have a \outnoun in $B$; the joint refinement lift asks that every finite set of them have
a common one.  The two agree when $B$ is directed.  Unlike the Hoare preorder,
the joint refinement lift is not reflexive: $A\LiftedOrd A$ holds exactly when $A$ is
directed, so the transaction fiber of Figure~\ref{fig:ambiguity-frames}(f)
already fails it at $j=i$.

\paragraph{The common-extension condition.}
Lifted Monotonicity compares an input with its
own input extensions. Runs may emit outputs at incomparable inputs, say
$o_1$ at $i_1$ and $o_2$ at $i_2$, and can be reconciled only at a common
\indesc $j$ of both. The next condition asks exactly that: a common
\outnoun of $o_1$ and $o_2$ in the fiber at $j$.

\begin{definition}[Common-extension condition]
\label{def:common-expansion-condition}
An \spectype satisfies the \emph{common-extension condition} when,
for every finite set of rows $(i_1,o_1),\ldots,(i_k,o_k)$ of $P$ and every
common \indesc $j$ of $i_1,\ldots,i_k$, some $u\in P(j)$ \outrel every
$o_r$.
\end{definition}

For the empty set of rows the condition asks only that $P(j)$ be nonempty, which
follows from $P$ being total on $I$.

\begin{proposition}[Common-extension form of Lifted Monotonicity]
\label{prop:common-expansion-form}
An \spectype satisfies Lifted Monotonicity if and only
if it satisfies the common-extension condition.
\end{proposition}

\begin{proof}[Proof sketch]
Relational Monotonicity carries each $o_r$ to some
\outnoun in the fiber at $j$, and because the spec has directed
fibers, those outputs have a common \outnoun there.  Full proof in Appendix~\ref{app:proofs-sec3}.
\end{proof}

\subsection{Lifted output events}
\label{sec:lifted-output-events}

For a state $(i,R)$ and $o\in R(i)$, the output event $\mathsf{output}(o)$
again emits $o$ and keeps exactly the rows whose outputs \outrelbase $o$,
ending at $(i,R[\mathrm{out}\OutputGe o])$ as in Equation~\ref{eq:output-action}.
Every later output must \outrelbase $o$, so the event removes the rows whose
outputs do not.  Each removed row $(k,x)$ falls into one of two classes:
subsumed or excluded.  A row $(k,x)$ is placed in $\Subsumed_o$ if some
$u\in R(k)$ \outrel both $x$ and $o$.  Then a later output $u$ reports
everything $x$ would have, and the removal, an output subsumption, loses
nothing.  Otherwise $(k,x)$ is placed in $\Excluded_o$, and the canonical
\commitment $x_o$ removes it.  If $x_o$ removes every row at $k$, it rules out
$k$; otherwise it rules out only those outputs.

These are the cases of Section~\ref{sec:ambiguity-story}: emitting $\bot$ under
the equality order of Figure~\ref{fig:nonmonotone-frame} puts the rows for
$aba$ and $abb$ in $\Excluded_o$ and rules out those inputs; emitting $[A,B]$
in Figure~\ref{fig:ambiguity-frames}(f) puts the row for $[B,A]$ in
$\Excluded_o$ and rules out that output at $\{A,B\}$; and the route sets removed
in panel~(g) are in $\Subsumed_o$.  In the functional case, $\Subsumed_o$ is
empty, so this is the output event of Definition~\ref{def:output-event}.
Appendix~\ref{app:lifted-output-events} gives the formal definitions.

With several outputs at one input, legality is more permissive: an output
event may remove rows by output subsumption without applying a \commitment.
As before, $o$ is a legal output when $\mathsf{output}(o)$ applies no
\commitment, exactly when $\Excluded_o$ is empty.  Equivalently, at every legal
\indesc $j$ of $i$, $o$ and each remaining output at $j$ have a common
\outnoun at $j$ (Proposition~\ref{prop:exposability}).

\subsection{The Complete CALM theorem}
\label{sec:complete-calm-theorem}

A lifted output event ends at $(i,R[\mathrm{out}\OutputGe o])$, as in
Equation~\ref{eq:output-action}.  Specification states, input events, runs,
\commitment-free runs, and consistency are defined as before.  The results of
Section~\ref{sec:executions} depend on output events only through that equation,
so the rows-remaining lemma (Lemma~\ref{lem:run-residual}) and survivor test
(Proposition~\ref{prop:confluence}) apply unchanged.  Thus consistency reduces
to Lifted Monotonicity.

\begin{theorem}[Complete CALM]
\label{thm:complete-calm}
An \spectype is consistent if and only if it satisfies Lifted
Monotonicity, equivalently the common-extension condition.
\end{theorem}

\begin{proof}[Proof sketch]
If the common-extension condition holds, a common \outnoun $u\in P(j)$
of everything emitted survives in every run.
If outputs emitted at inputs with a common \indesc $j$ are incompatible in
$P(j)$, the runs that emit them share no row at $j$ and can never be
reconciled there.  Full proof in Appendix~\ref{app:proofs-sec3}.
\end{proof}

The name CALM, for Consistency As Logical Monotonicity, tied the idea to a
logic language.  The new, more general result is Consistency As Lifted Monotonicity.
The condition that characterizes consistency is now a
property of a spec: Lifted Monotonicity, which for a function is
ordinary monotonicity.

The same condition governs legality.

\begin{proposition}[Output-legality boundary]
\label{prop:exposure-boundary}
An \spectype satisfies Lifted Monotonicity if and only
if every output at every state reachable without \commitment is legal.
\end{proposition}

\begin{proof}[Proof sketch]
Under the common-extension condition, consistency supplies the common \outnoun
the legal-output test asks for.  Conversely, the legal-output test at canonical
states, one row at a time, builds the common \outnoun the condition
asks for.  Full proof in Appendix~\ref{app:proofs-sec3}.
\end{proof}

For functions, both are monotonicity, so Complete CALM and
Proposition~\ref{prop:exposure-boundary} reduce to Functional CALM and
Proposition~\ref{prop:functional-exposure-boundary}.
