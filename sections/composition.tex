\section{Composition and Irredundant Coordination}
\label{sec:composition}

Prior literature presented a puzzle: the ``fix'' for a non-monotone
program is coordination, which is another non-monotone program. A key-value
store with mutable keys is non-monotone~\cite{alvaro2011bloom}. The standard
solution, as in state-machine replication~\cite{schneider1990smr}, is to wrap it
with a log. Clients send
requests, a log puts the requested commands in one order, and the key-value store
executes the log and answers each request.  The log's specification is also not
monotone: when two commands arrive concurrently, either may be appended next,
and the two resulting logs have no common \outnoun.  
Yet replicated stores are consistent, and they
coordinate only in the log.  Multi-Paxos agrees on each log
entry~\cite{lamport2001paxos}, and the replicas then execute the agreed log---the
key-value store needs no further agreement.

That puzzle is explained by our framework.  Specifications are
tables, so they compose by equijoin, and composition preserves Lifted
Monotonicity.  Because commitments are explicit, we
can also ask which component makes a composition's commitments.  When one
component makes every commitment the composition needs and the other makes
none, we call the coordination \emph{irredundant}
(Section~\ref{sec:irredundant-coordination}).  Example~\ref{ex:committed-log-composition}
returns to the replicated store.  Proofs are in
Appendix~\ref{app:composition}.
\label{sec:sequential-composition}

Intuitively, sequential composition feeds the output of one specification to
the input of the next.  The composite is again a table: it pairs an input of
the first specification with every output that the second permits for some
intermediate value that the first permits.  Formally, let
$\Spec_1=(I,\InputOrd,M,\preceq_M,S_1)$ and
$\Spec_2=(M,\preceq_M,O,\OutputOrd,S_2)$ be ordered relational specifications
sharing the ordered domain $(M,\preceq_M)$.  Their \emph{sequential
composition} has table
\begin{equation}
  S_2\circ S_1
  =\pi_{I,O}(S_1\Join_M S_2)
  =\{(i,o):\exists m.\ (i,m)\in S_1\land(m,o)\in S_2\},
  \label{eq:spec-composition}
\end{equation}
where $\pi$ and $\Join$ are relational projection and equijoin.  Since $S_1$
is total on $I$ and $S_2$ is total on $M$ (it has a row at every $m\in M$),
every $i\in I$ has a nonempty fiber in $S_2\circ S_1$.

\begin{lemma}[Composition]
\label{lem:composition}
If $\Spec_1$ and $\Spec_2$ satisfy Lifted Monotonicity, then the ordered
specification with table $S_2\circ S_1$ satisfies Lifted Monotonicity.
\end{lemma}

\begin{proof}[Proof sketch]
Take rows of $S_2\circ S_1$ whose inputs have a common \indesc $j$.  The
common-\indesc condition for $\Spec_1$ gives one intermediate value at $j$
that \outrel each row's intermediate value, and that value is a common \indesc
at which the condition for $\Spec_2$ supplies the common \outnoun.  Full proof
in Appendix~\ref{app:composition}.
\end{proof}

By associativity the lemma extends to finite pipelines.  For a function $f$,
its table $\{(i,f(i))\}$ satisfies Lifted Monotonicity exactly when $f$ is
monotone (Section~\ref{sec:lifted-monotonicity}). 

The CRDT observations of Section~\ref{sec:crdt-instance} have this shape: a
client query $q$ over the replica state $s$ is the composition $q\circ s$, and
compositions of monotone functions are monotone
(Corollary~\ref{cor:functional-composition}), so
monotonicity of $q$ on all of the state domain suffices.

\subsection{Composite CALM}
\label{sec:composite-calm}

The composite is itself an ordered specification, so Complete CALM applies to
it directly.  Specification $S_2\circ S_1$ is consistent exactly when it
satisfies Lifted Monotonicity, and then no output needs a commitment
(Theorem~\ref{thm:complete-calm}, Proposition~\ref{prop:exposure-boundary}).
Lemma~\ref{lem:composition} gives one way to meet that test.

A monotone composite does not mean that each component can run without
commitments.  Consider an upstream specification with one input and two
incomparable outputs, and a downstream function that maps both to the same
value.  The composite has one row, so it is monotone.  The upstream component
still cannot emit either output without choosing, so a pipeline in which
neither component commits never emits anything
(Appendix~\ref{app:composition}).  The test is on the table alone.  Which
component commits depends on the implementation, the subject of the next
subsection.

\subsection{Irredundant Coordination}
\label{sec:irredundant-coordination}

Intuitively, a replicated store coordinates once.  Multi-Paxos commits to an
order of concurrent commands, and the store executes whatever log it is given.
We now make this precise for a composition whose downstream component is a
function.

Let $\mathcal P=(I,\InputOrd,M,\preceq_M,P)$ be an upstream specification and
$f:(M,\preceq_M)\to(O,\OutputOrd)$ a function.  The \emph{store} $\mathcal K$
is the specification with table $\{(m,f(m))\}$, and the composite
$\mathcal K\circ\mathcal P$ has table $\{(i,f(m)):(i,m)\in P\}$.  For a state
$\sigma=(i,R)$ of $\mathcal P$, its \emph{image} $f(\sigma)$ is the state
$(i,\{(k,f(m)):(k,m)\in R\})$ of the composite.  Fix a system for
$\mathcal P$ (Definition~\ref{def:system}) with basis $\mathcal B$.  In the
\emph{guarded composite}, the store follows each participant: when the
participant emits $m$ by $\Out{\gamma}{m}$, the store receives $m$ and emits
$f(m)$.  The environment observes $\mathsf{input}(j)$ and $f(m)$.  We say that
$\mathcal P$ \emph{guards} $\mathcal K$, and that $\mathcal K$
\emph{delegates} commitment to $\mathcal P$.

One might push each commitment of $\mathcal P$ forward along $f$.  This does
not work.  A commitment of $\mathcal P$ may keep $m'$ and remove $m$, with $m$
and $m'$ incomparable but $f(m)\OutputOrd f(m')$.  Its image removes a row
\outrelpast by a row it keeps, which Equation~\ref{eq:commitment-excludes}
forbids.  In the composite, emitting $f(m')$ needs no commitment at all, since
it retires $f(m)$.  A choice upstream can become a retirement downstream.  We
therefore push forward runs, not commitments.

\begin{definition}[Irredundant Coordination]
\label{def:irredundant-coordination}
The guarded composite coordinates \emph{at most once} when every run of
$\mathcal P$ under $\mathcal B$, with each output $m$ replaced by $f(m)$, is a
run of $\mathcal K\circ\mathcal P$, and the store's part of it is a run of
$\mathcal K$ under the empty basis.  It coordinates \emph{at least once} when
every output event $\Out{\gamma}{m}$ of $\mathcal P$ at a state $\sigma$ such
that $f(m)$ is not exposable at $f(\sigma)$ has $\gamma\neq\varepsilon$.  It is
\emph{irredundant} when it coordinates at most once and at least once.
\end{definition}

At most once says that the store adds no commitment.  At least once says that
whatever commitment the composite needs, $\mathcal P$ makes.  Both halves are
needed, since a silent system trivially satisfies the first.

\begin{theorem}[Guarded runs]
\label{thm:guarded-runs}
Let $f$ be monotone and $\mathcal B$ any basis of $\mathcal P$.
\begin{enumerate}
  \item Every run of $\mathcal P$ under $\mathcal B$, with each output $m$
        replaced by $f(m)$, is a run of $\mathcal K\circ\mathcal P$ from the
        same canonical state.  After each event, the composite run's table
        contains the image of $\mathcal P$'s.
  \item The outputs of such a run form a chain, and the store's run on them
        is a run of $\mathcal K$ under the empty basis.
  \item If finitely many runs of $\mathcal P$ can be brought to a common state
        with current input $j$, under any bases, the corresponding composite
        runs are confluent at $j$.
\end{enumerate}
\end{theorem}

\begin{proof}[Proof sketch]
(1) By induction on events.  An output event $\Out{\gamma}{m}$ keeps only rows
that \outrel $m$ (Lemma~\ref{lem:canonical-commitment-normal-form}), and $f$
carries them to rows that \outrel $f(m)$, which the composite's
$\mathsf{output}(f(m))$ keeps.  (2) Each emitted output \outrel the earlier
ones, so the store's inputs grow, and every output of a monotone function is
exposable.  (3) A common state has a row $(j,m)$, so every composite run keeps
$(j,f(m))$, which gives confluence.  Full proof in
Appendix~\ref{app:composition}.
\end{proof}

\begin{theorem}[Irredundant Coordination]
\label{thm:irredundant-coordination}
If $f$ is monotone, the guarded composite is irredundant for every basis of
$\mathcal P$.  If moreover $\mathcal K\circ\mathcal P$ violates Lifted
Monotonicity, some output $f(m)$ of the composite is not exposable at a
canonical state, and $\mathcal P$ must commit to emit any output with that
image there.
\end{theorem}

\begin{proof}[Proof sketch]
At most once is Theorem~\ref{thm:guarded-runs}.  For at least once, suppose
$\mathcal P$ emits $m$ at $\sigma$ with no commitment, so $m$ is exposable at
$\sigma$.  A row of $\sigma$ retired to $(k,u)$ maps to a row of $f(\sigma)$
retired to $(k,f(u))$, so $f(m)$ is exposable at $f(\sigma)$.  When Lifted
Monotonicity fails, the exposure boundary already fails at a canonical state
(Proposition~\ref{prop:exposure-boundary}), and the image of a canonical state
is canonical.  Full proof in Appendix~\ref{app:composition}.
\end{proof}

The theorem holds for every basis of $\mathcal P$.  Multi-Paxos commits by
deciding log slots.  A design with per-key mutexes would instead order pairs of
commands on one key, as 2PL orders pairs of transactions where MVTO stamps
them (Section~\ref{sec:systems}, Appendix~\ref{app:cc-bases}).  Neither basis
need match the canonical commitments of the composite, and we need not compare
them.
Every legal output event removes at least the rows its canonical event
removes (Lemma~\ref{lem:canonical-commitment-normal-form}), so every row that
the composite must seal or choose against has lost all its preimages to
$\mathcal P$'s commitments (Appendix~\ref{app:composition}).

Some of $\mathcal P$'s commitments are invisible to the composite.

\begin{proposition}[Invisible coordination]
\label{prop:invisible-coordination}
Let $f$ be monotone, and let $\mathcal P$ emit $m$ at $\sigma$ by
$\Out{\gamma}{m}$.  If every row that $\gamma$ removes has a row with the same
input and the same image that $\gamma$ keeps, then $f(m)$ is exposable at
$f(\sigma)$.
\end{proposition}

Consider a store that answers each key from that key's commands, in log
order, and two commands $a$ and $b$ on different keys.  The log must order
them, since $[a,b]$ and $[b,a]$ have no common \outnoun.  The store's view of
both logs is the same, so the composite needs no commitment
(Appendix~\ref{app:composition}).  The order of $a$ and $b$ is coordination
inside $\mathcal P$ that the composite does not see.

\begin{example}[Replicated store]
\label{ex:committed-log-composition}
Consider again state-machine replication, with every put and get passing
through the log.  Take $I$ the proposal streams and $M$ the logs, both ordered
by prefix, and $O$ the cumulative response histories, ordered by extension.
Let $\mathcal P$ relate each proposal stream to the logs of its commands, and
let $f$ execute a log on a deterministic state machine, which is monotone in
the prefix order.  Then $\mathcal P$ is non-monotone, since distinct next
entries are incompatible outputs in one fiber.  So is the key-value store
$\mathcal K\circ\mathcal P$, since concurrent commands ordered oppositely give
incompatible responses.  Multi-Paxos runs $\mathcal P$ under its own basis,
deciding one log slot at a time~\cite{schneider1990smr,lamport2001paxos}.  By
Theorem~\ref{thm:irredundant-coordination}, the store needs no commitment of
its own, and because the composite is not monotone, the log's commitments
cannot be dropped.  The replicated store coordinates exactly once.
\end{example}

A downstream component often has input of its own, not only the output of the
component before it.  In a replicated store, for example, not every request
needs to pass through the log.  Some stores serve \emph{bare reads}: a client
sends a get directly to a replica, which answers from the log prefix it has
executed, without going through Multi-Paxos.  Bare reads avoid the cost of
coordination, at the risk of missing a fresher value that has already reached
another replica.  In Appendix~\ref{sec:parameterized-composition} we give
each component a separate input, in an \emph{independently parameterized
composition}, and Lemma~\ref{lem:composition} carries over.  There, bare reads
need no commitment of their own when each response records the log position it
read from, but they do when the specification demands the latest value
(Example~\ref{ex:bare-reads}).
