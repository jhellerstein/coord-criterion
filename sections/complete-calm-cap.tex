\section{Complete CALM and Complete CAP}
\label{sec:complete-calm}

The previous two sections developed orthogonal extensions of Functional CALM:
Lamport histories give Consistency a distributed reading, while relational
specifications add output choice.  We now combine them.  First we identify
coordination with commitment and state when conflicting output events cannot
coexist; then Complete CALM equates Consistency, Lifted Monotonicity, and
Distributed Consistency, and Complete CAP states the resulting partition
boundary.

\subsection{Coordination}
\label{sec:coordination}

Consistency is confluence: independently evolving states can still meet.
Coordination is its operational counterpart: the system makes a binding choice
that removes some otherwise possible behavior.  In our transition system, that
act is exactly a commitment.  A mutex, lock, atomic ordering mechanism, or
agreement protocol is in scope when it serves this role.  Computation or
communication that removes no such alternative is not coordination merely
because it uses one of these mechanisms.

\begin{definition}[Coordination]
\label{def:coordination}
A system execution \emph{coordinates} if and only if an output event applies a
commitment: it irrevocably removes a row that neither input nor output retirement
accounts for.  It is \emph{coordination-free} when its output events apply no
commitments; they may still perform output retirements.
\end{definition}

Throughout this section, \emph{reachable} means reachable without commitment
(Section~\ref{sec:determination}).

\begin{theorem}[Conflicting output events cannot coexist]
\label{thm:commitments-require-coordination}
Suppose one participant can perform an output event at a reachable state
$\sigma=(i,R)$ that applies a commitment, producing a state
$\sigma'=(i,R')$ in which some $x\in R(i)$ has been removed by commitment and
no output in $R'(i)$ refines $x$.  Suppose a second participant can
independently emit $x$ after receiving the same input events, obtaining a state
$t$ whose fiber at $i$ contains only refinements of $x$.  Then $\sigma'$ and
$t$ cannot be brought to a common state with current input $i$.
\end{theorem}

\begin{proof}
By hypothesis, the second participant can reach $t$, whose fiber at $i$ is
contained in $\{u\in\fiber{i}:x\OutputOrd u\}$.  The first participant's fiber
$R'(i)$ contains no such $u$.  Their fibers at $i$ are therefore disjoint, so
the two states cannot be brought to a common state whose current input is $i$.
Neither an output event nor an input event can restore a removed row or return
to $i$.
\end{proof}

If both output events must remain independently available, a system must
mutually exclude them before either participant commits.  In a shared-memory
system a mutex or atomic instruction provides that exclusion; in a distributed
system, agreement is one way to establish it.  Static authority or a
predetermined strategy can instead make one event unavailable, in which case no
runtime agreement follows from the theorem.

\subsection{The Complete CALM theorem}
\label{sec:complete-calm-theorem}

Complete CALM turns the coordination boundary into a property of the
specification.  It equates Consistency---confluence of canonical runs---with
Lifted Monotonicity.  The distributed execution model
supplies the equivalent third view, Distributed Consistency.

Its proof is assembled from parts already in hand: the common-refinement
characterization of Consistency, which lifts unchanged to output choice
(Section~\ref{sec:relational-executions}); the identification of Lifted
Monotonicity with the common-refinement condition; and the distributed reading
of Consistency.

\begin{theorem}[Complete CALM]
\label{thm:complete-calm}
For an ordered relational specification, the following are equivalent:
\begin{enumerate}
  \item Consistency;
  \item Lifted Monotonicity;
  \item Distributed Consistency.
\end{enumerate}
\end{theorem}

\begin{proof}
Items~(1) and~(3) are equivalent by
Proposition~\ref{prop:distributed-consistency}.  By
Theorem~\ref{thm:common-refinement}, Consistency is equivalent to the
common-refinement condition, which is form~(3) of
Proposition~\ref{prop:lifted-monotonicity-decomposition} and hence equivalent
to Lifted Monotonicity.
\end{proof}



The theorem gives a specification-level test for history confluence.  It also
derives exposability rather than assuming it: by the exposure boundary
(Proposition~\ref{prop:functional-exposure-boundary}), Lifted Monotonicity holds
exactly when every output at every reachable state is exposable.

Thus Lifted Monotonicity makes all reachable outputs exposable, so output
progress needs no commitment and is coordination-free.  Its failure exhibits
a finite family without a common refinement, so selecting an offending output
requires a commitment and hence coordination.  When different participants
must retain independently selectable conflicting alternatives,
Theorem~\ref{thm:commitments-require-coordination} applies.

Output choice also separates safety from liveness.  Confluence guarantees that
for any finite history, some extension brings every participant to a common
state.  In the functional case, finding that extension is trivial: the state is
determined by the input (Corollary~\ref{cor:state-by-input}), so delivering the
full input suffices.  With several outputs per input, the state also depends on
which outputs have been emitted (Lemma~\ref{lem:run-residual}).  Participants at
a common input $j$ must emit some $u\in\fiber{j}$ above everything any of them
has emitted, and Lifted Monotonicity guarantees that such a $u$ exists.
Whether they reach it is a matter of strategy.  Participants that choose
independently may keep emitting new outputs, each needing its own
reconciliation.  One strategy that terminates is deterministic reconciliation:
participants that share knowledge of the inputs and emitted outputs apply the
same rule for choosing $u$, and arrive at the same state without any
commitment.  Section~\ref{sec:discussion} returns to this distinction.

\subsection{The Complete CAP Theorem}
\label{sec:cap-corollary}

The coordination boundary becomes an availability boundary during a
partition: participants in different components cannot establish a new shared
commitment.  A \emph{partitioned history} divides participants into two or more
components and has no cross-component message receive while the partition
lasts, though participants may still receive environment input and emit
outputs.  Each participant has one state at a cut.

We use an interface-wide form of \emph{Availability}: every output in a
participant's current fiber can be emitted by an output event without
commitment and without waiting for a message from another component.  This is
stronger than requiring some response to one operation, because the full
declared interface treats every permitted output as available.  The history has
\emph{Partition Consistency} when its participant projections are confluent,
through commitment-free extensions, at every common refinement of their current
inputs.

The partition's only effect is to forbid new shared commitments across
components.  Availability therefore reduces to exposability, and Complete CAP
follows from Complete CALM and the exposure boundary; its content is that the
boundary is exact.

\begin{theorem}[Complete CAP]
\label{thm:complete-cap}
For an ordered relational specification $\Spec$, the following are equivalent:
\begin{enumerate}
  \item every consistent cut of every commitment-free partitioned
        history has Availability and Partition Consistency;
  \item $\Spec$ satisfies Lifted Monotonicity.
\end{enumerate}
\end{theorem}

\begin{proof}
Suppose first that $\Spec$ satisfies Lifted Monotonicity.  Each
participant's projection is commitment-free and hence a canonical run
(Section~\ref{sec:determination}), so every output at its state is exposable by
the exposure boundary (Proposition~\ref{prop:functional-exposure-boundary}),
giving Availability.  Complete CALM and the survivor test supply a row $(j,u)$
surviving in every projection.  After $\mathsf{input}(j)$, each participant's
state is again reachable without commitment, so $u$ is exposable there and its
output event needs no commitment; this gives Partition Consistency.

Conversely, let any finite rows $(i_r,o_r)$ have a common refinement $j$.
Place their participants in separate partition components.  If there is only
one row, add a second participant initialized at $j$ and emit no output there.
Availability lets each original participant perform $\mathsf{output}(o_r)$
from $\sigma_S(i_r)$ without a commitment.  Partition Consistency and the
survivor test then supply a row $(j,u)$ surviving in every remainder table,
so containment gives $o_r\OutputOrd u$ for every $r$.  Form~(3) of
Proposition~\ref{prop:lifted-monotonicity-decomposition} gives Lifted
Monotonicity.
\end{proof}

Partition Consistency requires outputs from different components to be jointly
refinable, not identical or totally ordered; this is why the characterization
is bidirectional.  When Lifted Monotonicity fails, some permitted output event
either requires a commitment that cannot be established without waiting for
another component, sacrificing Availability, or completes independently at
the cost of Partition Consistency.

A linearizable register is the classical instance of the tradeoff side: a
write completed in one partition component is hidden from a read in another,
so indistinguishable local executions force the reader either to wait or to
violate real-time order.  Whether a commitment requires agreement across a
partition also depends on which participant may hold which input and make which
choice.  Appendix~\ref{app:deployment} introduces a weaker, deployment-relative
availability condition that counts partition-independent local commitments as
available, sets aside the degenerate case in which one participant holds all
relevant authority, and shows that a causal register needs no cross-component
coordination when each participant answers only its own reads.  With the
central results in place, we now compare their consequences across the
surrounding literature.
